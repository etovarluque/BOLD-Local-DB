BOLD DB
Instrucciones de instalación y uso — Base de datos local de BOLD
Windows Python 3.10+ 🌐 English version

1 ¿Para qué sirve?

Esta herramienta descarga los registros públicos del sistema BOLD (Barcode of Life Data System) y los convierte en una base de datos local que puedes consultar desde tu navegador, sin necesidad de internet una vez instalada.

Son dos programas, y se usan en ese orden:

ProgramaPara qué sirveCómo se abre
BOLD DB Creator Procesa el archivo descargado de BOLD y construye la base de datos Acceso directo 1_Crear_base_de_datos
(equivale a dev/bold_db_creator.bat)
Visor web BOLD DB Permite buscar y exportar registros una vez que la base está construida Acceso directo 2_Abrir_visor_web_BD_BOLD
(equivale a dev/launch_bold_db.bat)
ℹ️
Los dos accesos directos están en la carpeta principal BOLD_DB/. Si copias el proyecto a otro equipo o a otra unidad y los accesos dejan de funcionar, ejecuta una vez Reparar_accesos.bat: los regenera apuntando a la ubicación actual.

2 Requisitos previos

Solo necesitas tener instalado:

  • Python 3.10 o superior — descárgalo desde python.org. Durante la instalación marca la opción "Add Python to PATH".
  • Espacio en disco: al menos 80 GB libres (ver preguntas frecuentes).
ℹ️
Las librerías necesarias se instalan automáticamente la primera vez que ejecutas cada programa: PySide6 para el Constructor, y Flask y psutil para el visor web. Solo necesitas conexión a internet en ese primer arranque.

3 Estructura de carpetas

Cuando abras la carpeta del proyecto verás esta organización:

BOLD_DB/
├── 1_Crear_base_de_datos       ← acceso directo al Constructor
├── 2_Abrir_visor_web_BD_BOLD   ← acceso directo al visor web
├── Reparar_accesos.bat         ← regenera los accesos si mueves la carpeta
├── data/
│   ├── raw/          ← aquí debes colocar el archivo descargado de BOLD
│   ├── processed/    ← archivos intermedios (TSV filtrado); se crea sola
│   └── exports/      ← copia de todo lo que exportas; se crea sola
├── dev/
│   ├── bold_db_creator.bat
│   └── launch_bold_db.bat
├── guide/            ← esta guía
└── app/              ← se crea sola: base de datos, servidor web y registros
    ├── bold_db.db    ← la base de datos terminada
    └── logs/         ← historial de cada ejecución del Constructor
✅
No tienes que crear ninguna carpeta a mano, salvo data/raw/ si no existiera. La carpeta app/ se genera automáticamente la primera vez que abres el Constructor, con todo lo necesario para el visor web.

4 Construir la base de datos

Solo necesitas hacer esto una vez, o cuando descargues una versión nueva de BOLD.

Descargar el archivo de BOLD

  1. Desde bench.boldsystems.org/index.php/datapackages/Latest descarga el archivo completo de datos (se requiere de una cuenta en BOLD). Tendrá un nombre similar a BOLD_Public.DIA-MES-AÑO.tar.gz.
  2. Copia ese archivo .tar.gz dentro de la carpeta BOLD_DB/data/raw/ — copiarlo, no moverlo (ver el aviso siguiente).
  3. No descomprimas el archivo; el programa lo hace solo.
⚠️
El .tar.gz se elimina automáticamente. Al terminar el Paso 1, el Constructor borra de data/raw/ tanto el .tar.gz como el TSV sin filtrar, para liberar los 10–15 GB que ocupan una vez ya procesados.

Por eso conviene copiar el archivo descargado a data/raw/ y no moverlo: así conservas el original en tu carpeta de descargas. Si algo falla a mitad del proceso, o quieres reconstruir la base más adelante, vuelves a copiarlo sin tener que descargar otra vez esos 10–15 GB desde BOLD.
⚠️
Deja un solo archivo .tar.gz en data/raw/. Si hay varios, el Constructor usa el más reciente y elimina los demás.

Elegir los campos que se guardan (opcional)

El panel Campos, en la barra lateral del Constructor (sección CONFIGURACIÓN), decide qué columnas del archivo de BOLD terminan en la base de datos. Trae marcadas por defecto las 23 columnas de siempre (ver Campos disponibles), pero puedes activar cualquiera de las 76 que ofrece el paquete público de BOLD — coordenadas de colecta, hábitat, cebadores, institución, etc.

  1. Marca o desmarca los campos que quieras guardar. Los que aparecen con un candado (ID BOLD, ID Muestra, BIN, taxonomía básica, Marcador, Secuencia…) no se pueden quitar: el visor los necesita para funcionar.
  2. Junto a cada campo marcado hay una segunda casilla, "búsqueda rápida": actívala en los campos por los que realmente vayas a buscar (crea un índice en el Paso 3 y los incluye en la búsqueda de texto completo del Paso 4). Déjala apagada en campos que solo quieres ver o exportar — cada índice cuesta espacio en disco.
  3. Pulsa "Guardar selección" para escribirla en dev/fields_config.json.
ControlQué hace
Restablecer camposVuelve a marcar en la lista los 23 campos de fábrica. Solo cambia lo que ves: no toca el archivo hasta que pulses "Guardar selección".
Comprobar con el TSVRelee la cabecera del archivo descargado y avisa si algún campo configurado ya no existe, o si BOLD añadió campos nuevos que no estás usando. Solo está disponible una vez descomprimido el .tar.gz (durante o después del Paso 1).
⚠️
Cambiar la selección obliga a repetir el Paso 1 con el .tar.gz de BOLD, porque los campos se extraen al filtrar el TSV. El programa detecta el cambio solo y vuelve a filtrar automáticamente si el .tar.gz sigue disponible; si ya se borró (se elimina al terminar el Paso 1), tendrás que volver a descargarlo para aplicar la nueva selección.
ℹ️
Si BOLD renombra o retira un campo en una versión nueva, el panel lo marca en rojo ("no está en el TSV") y, si encuentra un nombre parecido en la cabecera nueva, lo sugiere. Un campo que BOLD ofrece y que no tienes activado aparece en ámbar ("nuevo en BOLD"). Si el campo ausente es uno de los que el visor necesita para funcionar, el Paso 1 se detiene con un mensaje explicando cuál falta, en vez de construir una base de datos incompleta.

Opción A — Ejecutar todos los pasos al tiempo (recomendado)

  1. Haz doble clic en el acceso directo 1_Crear_base_de_datos. Se abrirá el Constructor.
  2. En el panel izquierdo, sección ATAJOS, haz clic en "Crear DB (1, 2, 3)".
  3. Confirma en el diálogo que aparece.
  4. Espera a que finalice. El proceso puede tardar varias horas dependiendo del tamaño del archivo y la velocidad de tu computadora.
✅
Cuando termine verás en el panel de salida: Pipeline completo — X,XXX,XXX registros listos.

Este atajo ejecuta los pasos 1, 2 y 3. El paso 4 (FTS) es opcional y se lanza aparte.

Opción B — Ejecutar los pasos uno a uno

Útil si necesitas retomar desde un punto específico o quieres ver el detalle de cada etapa.

Paso 1 — Generar TSV (obligatorio)

Descomprime el archivo .tar.gz y extrae solo las columnas marcadas en el panel Campos — 23 por defecto, ajustable.

  • Selecciona "1. Generar TSV" en el menú izquierdo → clic en Ejecutar.
  • Duración aproximada: 10–40 minutos.
  • Resultado: un archivo .filt.tsv en data/processed/.
  • Al terminar se borran de data/raw/ el .tar.gz y el TSV sin filtrar, para liberar espacio. Si copiaste el archivo en vez de moverlo, tu descarga original sigue intacta donde estaba.
  • Antes de filtrar, el programa verifica que los campos configurados existan en la cabecera real del archivo descargado — ver panel Campos.

Paso 2 — TSV → SQLite (obligatorio)

Importa los datos filtrados a la base de datos.

  • Selecciona "2. TSV → SQLite" → clic en Ejecutar.
  • Duración aproximada: 30–90 minutos.
  • Resultado: el archivo app/bold_db.db.

Paso 3 — Indexar campos (recomendado)

Crea índices para que las búsquedas sean rápidas. Sin este paso la base funciona, pero cada consulta puede tardar minutos en vez de segundos.

  • Selecciona "3. Indexar campos" → clic en Ejecutar.
  • Duración aproximada: 5–20 minutos.

Paso 4 — Crear FTS (opcional)

⚠️
Este paso es opcional. Tarda varios minutos (unos 5–15 según el tamaño de la base) y añade aproximadamente un 25% al tamaño de la base de datos. Una vez iniciada la reconstrucción del índice no se puede interrumpir, pero al ser rápida no supone mayor riesgo. Solo es necesario si quieres usar la pestaña "Búsqueda de texto completo".
  • Selecciona "4. Crear FTS" → clic en Ejecutar.
  • Por defecto el índice cubre casi los mismos campos que la búsqueda por campos (19 de 20): ID Muestra, ID Campo, ID Museo, BIN, taxonomía completa (reino a especie), identificación, ID Nivel, país, estado, región, Bases, marcador y fecha de secuencia. Queda fuera código país (ver nota más abajo). Esta lista depende de qué campos hayas marcado como "búsqueda rápida" en el panel Campos; si cambiaste la selección, puede ser distinta.

Indicadores de estado

En cada panel verás debajo de la descripción del paso:

IndicadorSignificado
Entrada disponible Los archivos necesarios para este paso están listos.
Entrada no encontrada Debes completar el paso anterior primero.

Reanudar y actualizar

El Constructor detecta el trabajo ya hecho y se salta lo que no hace falta repetir:

  • Si el TSV filtrado ya existe, el Paso 1 se omite.
  • Si la base ya se construyó desde ese mismo TSV, el Paso 2 se omite.
  • Solo se crean los índices que aún faltan.
  • Si el FTS corresponde a los datos actuales, el Paso 4 se omite.

Para actualizar a una versión nueva de BOLD: coloca el nuevo .tar.gz en data/raw/ y vuelve a ejecutar el atajo "Crear DB (1, 2, 3)". Los archivos de la versión anterior se eliminan automáticamente y la base se reconstruye desde cero.

⚠️
Si interrumpes un paso con el botón Detener, los archivos parciales se borran para evitar datos corruptos. Al volver a ejecutar, ese paso empieza de nuevo.

Registro de actividad

Cada ejecución del Constructor deja su propio registro:

ArchivoContenido
app/logs/run_AAAA-MM-DD_HH-MM-SS.logTodo lo que apareció en el panel de salida durante esa sesión. Se conservan los 100 más recientes.
app/logs/error.logDetalle técnico de los errores. Es el archivo que hay que revisar cuando algo falla.

5 Consultar la base de datos

Abrir la base de datos

Haz doble clic en el acceso directo 2_Abrir_visor_web_BD_BOLD. Se abrirá una ventana de terminal y automáticamente el navegador en http://127.0.0.1:5001.

⚠️
La ventana de terminal debe permanecer abierta mientras uses la base de datos. Si la cierras, el navegador dejará de funcionar y verás el aviso "SIN CONEXIÓN AL SERVIDOR".

Arriba a la derecha de la página aparece la versión de BOLD cargada, y junto al título el número total de registros de la base.

Modos de búsqueda

📋 Búsqueda avanzada por campos

Filtra registros combinando condiciones sobre columnas específicas: especie, país, marcador, BIN, etc.

🔍 Búsqueda de texto completo

Busca una o varias palabras en todos los campos de texto a la vez. Requiere haber completado el Paso 4.

📦 Búsqueda en Batch

Busca una lista entera de valores cargando un archivo de texto. Ideal para muchas especies o IDs a la vez.

Búsqueda avanzada por campos

  1. Deja el primer selector (AND / OR / NOT) como está: en la primera condición no tiene efecto.
  2. Elige el campo por el que quieres buscar (ej. Especie, País, BIN).
  3. Elige el operador.
  4. Escribe el valor. Aparecerán sugerencias de autocompletar.
  5. Haz clic en Buscar o presiona Enter.

Para buscar con varias condiciones, haz clic en "+ Añadir condición". El selector AND / OR / NOT de cada nueva fila indica cómo se une esa condición con las anteriores.

ConectorSignificadoEjemplo
ANDAmbas condiciones deben cumplirsePaís = Colombia AND Marcador = COI-5P
ORAl menos una condición debe cumplirseEspecie = Panthera leo OR Especie = Panthera onca
NOTExcluir los que cumplen esa condiciónFamilia = Felidae NOT Género = Felis
ℹ️
Las condiciones se evalúan en orden, de arriba hacia abajo, sin paréntesis. Si necesitas agrupar, divide la consulta en dos búsquedas o usa el modo Batch.

Búsqueda de texto completo

ℹ️
Disponible solo si completaste el Paso 4 (Crear FTS).
  1. Escribe una o varias palabras en el cuadro de búsqueda.
  2. Haz clic en Buscar o presiona Enter.

Por defecto la búsqueda recorre casi los mismos campos que la búsqueda por campos (19 de 20): ID Muestra, ID Campo, ID Museo, BIN, reino, filo, clase, orden, familia, género, especie, identificación, ID Nivel, país, estado, región, Bases, marcador y fecha de secuencia — la lista exacta depende de qué campos marcaste como "búsqueda rápida" en el panel Campos. No busca dentro de la secuencia de ADN, las coordenadas, el ID BOLD (ya tiene su propia búsqueda exacta como identificador único de registro) ni el código país: al ser siempre de 2 letras (ej. "CO", "US"), es demasiado corto para el tipo de índice que usa esta búsqueda — usa el país (nombre completo) o la búsqueda por campos con Código País = ....

Lo que escribesResultado
PantheraRegistros que contienen esa palabra en cualquier campo de texto, incluso como parte de otra palabra (ej. también encuentra "Pantherinae")
Panthera ColombiaAmbas palabras presentes, en cualquier campo, no necesariamente el mismo (equivale a AND)
Panthera AND ColombiaAmbas palabras presentes, en cualquier campo
Panthera OR FelisCualquiera de las dos palabras
Panthera NOT leoPanthera pero sin leo
"Ara macao"Frase exacta: busca esa secuencia de texto completa y contigua dentro de un mismo campo
MexicoTambién encuentra México: los acentos se ignoran
ℹ️
Sin comillas, cada palabra se busca por separado en cualquier campo de texto, y todas deben aparecer en el registro (aunque sea en columnas distintas y sin relación entre sí). Esto puede producir coincidencias inesperadas: buscar Ara macao sin comillas también encuentra registros donde "Ara" aparece como fragmento de otra palabra en un campo (ej. el género Hylarana, que contiene "ara") y "macao" coincide por separado con otro campo (ej. una región llamada Macao), aunque el registro no tenga nada que ver con el ave.

Con comillas ("Ara macao") la búsqueda exige que el texto aparezca completo y seguido dentro de un mismo campo, eliminando ese tipo de coincidencias cruzadas — es la forma recomendada de buscar un nombre de especie de dos palabras.
⚠️
Buscar un valor de Bases de solo 1 o 2 dígitos (ej. 34) no encuentra nada, por la misma razón que el código país: el índice no puede representar textos de menos de 3 caracteres. Con 3 dígitos o más (ej. 658) funciona con normalidad.
⚠️
Los conectores AND, OR y NOT deben escribirse en MAYÚSCULAS. Fuera de una frase entre comillas, los símbolos ( ) * : . - + | & ! ^ se tratan como texto literal, no como sintaxis: el asterisco no funciona como comodín y los paréntesis no agrupan. Dentro de una frase entre comillas, AND/OR/NOT tampoco actúan como conectores: se buscan como palabras literales de la frase.

Búsqueda en Batch

Ideal cuando tienes una lista de especies, BINs o IDs y quieres obtener todos sus registros a la vez.

La Búsqueda en Batch es, en esencia, una búsqueda por campos automatizada: repite la misma consulta una vez por cada término de tu archivo. Eso implica que todos los términos del archivo deben pertenecer a un mismo campo, el que selecciones en Campo 1. El programa no deduce a qué categoría pertenece cada línea: aplica el campo elegido a todas por igual.

⚠️
No mezcles categorías dentro del archivo. Una lista con Panthera leo, COI-5P y Colombia no funciona: son valores de tres campos distintos (Especie, Marcador y País). Si buscas con Campo 1 = Especie, solo Panthera leo arrojará resultados y los otros dos aparecerán en not_found.txt.

Para cruzar dos campos —por ejemplo, esas especies únicamente en ciertos países— no los juntes en un archivo: usa dos archivos separados con la opción "Agregar segundo campo de filtro".

Única excepción: dentro de la taxonomía sí puedes mezclar niveles (familias, géneros y especies en el mismo archivo), porque los términos de una sola palabra se buscan en todos los niveles a la vez. Ver Cómo se interpretan los términos taxonómicos, más abajo.
  1. En Campo 1, selecciona la columna que corresponde a los términos de tu archivo (ej. Especie si el archivo contiene nombres de especies).
  2. Arrastra un archivo .txt o .csv al área indicada (un valor por línea), o haz clic en "examina".
  3. Opcionalmente, activa "Agregar segundo campo de filtro" y carga una segunda lista para restringir por otro campo (ej. esas especies solo en ciertos países).
  4. Si necesitas las secuencias en formato FASTA, marca "Exportar también en formato FASTA".
  5. Opcionalmente, abre "⚙ Personalizar reporte resumen" para añadir columnas al summary.csv (ver Personalizar el reporte resumen).
  6. Haz clic en "Buscar en Batch" y espera; al terminar se descarga un archivo ZIP.

Cómo se interpretan los términos taxonómicos

Si el Campo 1 es taxonómico (reino, filo, clase, orden, familia, género o especie):

  • Un término de una sola palabra (ej. Felidae) se busca en todos los niveles a la vez: reino, clase, orden, familia, género y especie. No hace falta acertar el nivel exacto.
  • Un término de dos palabras (ej. Panthera leo) se busca solo en Especie.
  • Los guiones bajos se convierten en espacios (Panthera_leo = Panthera leo), la primera letra se pone en mayúscula y se descartan los duplicados.

Para cualquier otro campo (BIN, marcador, IDs, país…) la coincidencia es exacta, sin distinguir mayúsculas.

Personalizar el reporte resumen

Por defecto, summary.csv responde una sola pregunta: cuántos registros hay por término. El panel "⚙ Personalizar reporte resumen" permite añadir columnas antes de lanzar la búsqueda, para responder también cuántos valores distintos de otro campo tiene cada término y cuáles son.

Ejemplo: buscando una lista de especies, puedes pedir el número de países y cuáles, más el número de marcadores genéticos y cuáles. El resumen queda así:

EspecieRegistros# PaísPaís# MarcadorMarcador
Panthera leo93Kenya (5); Tanzania (3); India (1)2COI-5P (8); ND2 (1)
Panthera onca51Brazil (4)1COI-5P (5)

Controles del panel

ControlQué hace
#Añade una columna con el número de valores distintos de ese campo para cada término
cuálesAñade una columna con la lista de esos valores, ordenada del más frecuente al menos frecuente
Incluir conteo por valorEscribe cuántos registros aporta cada valor: Kenya (400); Tanzania (100)

↺ RestablecerQuita toda la personalización y vuelve al resumen básico
ℹ️
Tu selección se recuerda para las siguientes búsquedas, igual que la configuración de columnas de la tabla. Junto al botón del panel verás un resumen de lo activo ("3 métricas · 1 desglose") sin necesidad de abrirlo.
ℹ️
Si no marcas nada, no cambia nada: el summary.csv sale exactamente como siempre y la búsqueda no tarda más. Las métricas se calculan mientras se arma el ZIP, así que incluso con varias marcadas el tiempo extra es mínimo.
⚠️
Solo se ofrecen campos de categoría: nivel taxonómico, marcador, país, estado, fecha de secuencia y las siete categorías taxonómicas (reino a especie). Quedan fuera BIN, los identificadores (ID BOLD, ID Muestra, ID Campo, ID Museo), las coordenadas y la secuencia, porque ahí casi cada registro tiene un valor propio: el conteo sería igual al de registros y la lista, ilegible.

Con Campo 2 activado, las métricas se calculan por cada combinación de Campo 1 × Campo 2, no agregadas por término. Si buscas especies filtradas por marcador, la fila Panthera leo / COI-5P mostrará los países de esa especie en ese marcador, y la fila Panthera leo / ND2 los suyos por separado.

Trabajar con la tabla de resultados

Los resultados se muestran en páginas de 50 registros. Bajo la tabla puedes avanzar página a página o escribir directamente el número de página al que quieres saltar.

Exportar resultados

Después de cualquier búsqueda aparecen los botones de exportación en la esquina superior derecha de los resultados. La exportación incluye todos los registros encontrados, no solo la página que estás viendo.

Exportar CSV

Abre un diálogo con dos opciones: incluir la columna de secuencia de ADN (sin ella la exportación es 2–3× más rápida) y exportar solo las columnas visibles según tu selección del botón "Columnas".

Exportar FASTA

Solo las secuencias de ADN, en formato estándar para análisis filogenéticos y alineamientos.

ℹ️
Las dos opciones del diálogo CSV son excluyentes: al marcar "solo columnas visibles" se deshabilita la exportación de la secuencia.

Formato de los archivos FASTA

Cada encabezado combina los datos disponibles del registro, separados por |:

# Exportación desde la tabla de resultados
>ID_BOLD|ID_Muestra|BIN|Especie|Marcador

# Exportación desde Búsqueda en Batch
>ID_BOLD|ID_Muestra|BIN|Taxón_más_específico|Marcador
  • El taxón más específico es el primero disponible en este orden: especie, género, familia, orden, clase, filo, reino.
  • Se eliminan los guiones de alineamiento y las N de los extremos.
  • Las secuencias de menos de 50 bases se descartan.
ℹ️
Para archivos grandes la exportación se procesa en segundo plano con una barra de progreso; cuando termina aparece un botón de descarga. Una copia queda guardada en data/exports/ (subcarpetas csv_exports, fasta_exports y batch_exports); en cada una se conservan los 20 archivos más recientes y los anteriores se borran solos.

7 Preguntas frecuentes

¿Cuánto espacio en disco necesito?
El archivo .tar.gz de BOLD pesa aproximadamente 10–15 GB. La base de datos SQLite resultante ocupa entre 20 y 30 GB. El índice FTS (Paso 4, opcional) añade en torno a un 25% más sobre ese tamaño. Se recomiendan al menos 80 GB libres. Ten en cuenta que durante el Paso 1 conviven temporalmente el .tar.gz, el TSV extraído y el TSV filtrado.
¿Tengo que crear la carpeta app/ antes de construir la base?
No. El Constructor la crea automáticamente al abrirse, junto con el servidor web, las plantillas y la carpeta de registros. Tú solo debes colocar el .tar.gz en data/raw/.
¿Puedo cerrar el Constructor mientras procesa?
No. Cerrar la ventana detiene el proceso. Si lo cierras accidentalmente, vuelve a abrirlo y ejecuta el paso de nuevo; el programa detecta el progreso previo y retoma desde donde corresponde.
El navegador dice "SIN CONEXIÓN AL SERVIDOR".
Significa que la ventana de terminal del servidor está cerrada. Vuelve a abrir el acceso directo 2_Abrir_visor_web_BD_BOLD.
La pestaña "Búsqueda de texto completo" no devuelve nada.
Requiere el Paso 4 (Crear FTS). Si no lo ejecutaste, usa la búsqueda por campos, que funciona siempre.
Busqué Panthera leo sin comillas en texto completo y me devolvió resultados de más.
Sin comillas, cada palabra se busca por separado en cualquier campo (equivale a Panthera AND leo), así que un registro puede colarse si contiene "Panthera" en un campo y "leo" en otro sin relación entre sí. Usa comillas — "Panthera leo" — para exigir esa secuencia exacta y contigua dentro de un mismo campo.
Las búsquedas tardan mucho.
Verifica que ejecutaste el Paso 3 (Indexar campos). Además, los operadores Contiene, No contiene y Termina con no pueden aprovechar los índices; cuando sea posible prefiere Es igual a o Comienza con.
¿Dónde quedan los archivos que exporto?
Se descargan por el navegador a tu carpeta de descargas habitual, y además se guarda una copia en data/exports/. De cada tipo de exportación se conservan los 20 archivos más recientes.
¿Puedo agregar o quitar campos de la base de datos?
Sí, desde el panel Campos del Constructor — ver Elegir los campos. Puedes activar cualquiera de las 76 columnas del paquete público de BOLD, no solo las 23 de fábrica. Un puñado de campos (ID BOLD, ID Muestra, BIN, taxonomía básica, Marcador, Secuencia) no se pueden quitar porque el visor los necesita para funcionar.
Cambié la selección de campos, guardé, pero el visor sigue mostrando lo mismo.
Guardar la selección solo actualiza dev/fields_config.json; la base de datos no cambia hasta que repites el Paso 1 con el .tar.gz de BOLD (el programa detecta el cambio y vuelve a filtrar solo). Si ya se borró el .tar.gz, tendrás que descargarlo de nuevo.
¿Con qué frecuencia debo actualizar la base de datos?
BOLD publica nuevas versiones semanalmente. Para actualizar, descarga el nuevo .tar.gz, colócalo en data/raw/ y vuelve a ejecutar los pasos 1–3. El programa elimina automáticamente la versión anterior.
¿Puedo tener la base de datos en un disco externo?
Sí. Copia toda la carpeta BOLD_DB/ al disco externo y ejecuta una vez Reparar_accesos.bat para que los accesos directos apunten a la nueva unidad.
¿Qué hago si el Paso 1 dice "Entrada no encontrada" aunque puse el archivo?
Verifica que el archivo esté directamente dentro de data/raw/ y que su extensión sea .tar.gz (no .tar ni .gz solo). El programa busca exactamente ese formato.
Algo falló y el mensaje no me dice lo suficiente.
Abre app/logs/error.log: contiene el detalle técnico del último error. El historial completo de cada sesión está en app/logs/run_*.log.
