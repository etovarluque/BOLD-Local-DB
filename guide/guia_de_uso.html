BOLD DB
Instrucciones de instalación y uso — Base de datos local de BOLD
Windows · macOS · Linux 🌐 English version

1 ¿Para qué sirve?

Esta herramienta descarga los registros públicos del sistema BOLD (Barcode of Life Data System) y los convierte en una base de datos local que puedes consultar desde tu navegador, sin necesidad de internet una vez instalada.

Tiene dos partes, y se usan en ese orden:

PartePara qué sirveCómo se abre
BOLD-Local-DB Procesa el archivo descargado de BOLD y construye o actualiza la base de datos Acceso directo BOLD-Local-DB, o Start BOLD-Local-DB en la carpeta del programa
Visor web Permite buscar, analizar y exportar registros una vez que la base está construida Acceso directo Visor BOLD-Local-DB, o el botón Abrir el visor en Inicio
ℹ️
Los accesos directos se crean desde la pantalla Inicio (en el escritorio, en el menú o en ambos). Si mueves la carpeta del programa a otro disco, se rehacen solos la próxima vez que lo abras.

2 Instalación

  1. Descarga el zip de tu sistema desde la página de Releases del proyecto en GitHub (BOLD-Local-DB-windows.zip, -macos.zip o -linux.zip) y descomprímelo donde quieras.
  2. Abre Start BOLD-Local-DB dentro de la carpeta descomprimida (.bat en Windows, .command en macOS, .sh en Linux).
  3. La primera vez descarga su propio Python y los componentes que necesita (unos 150 MB, solo una vez). Después se abre el programa y te ofrece crear los accesos directos.

No hace falta instalar Python ni nada más: todo queda dentro de la carpeta del programa. Necesitas además:

  • Espacio en disco: al menos 80 GB libres (ver preguntas frecuentes).
  • Internet la primera vez que abres el programa, para descargar BOLD y para el Lote en GenBank.
ℹ️
macOS: la primera vez, macOS bloquea el archivo descargado. Haz clic derecho sobre Start BOLD-Local-DB.command → Abrir → Abrir. Solo una vez.
Linux: si al hacer doble clic el .sh se abre en un editor de texto, permite ejecutar archivos en tu gestor de archivos o ábrelo desde una terminal.
✅
Actualizar el programa: cuando hay una versión nueva, la pantalla Inicio lo avisa. El botón Actualizar la descarga y reinicia el programa con ella; tu base de datos y tus archivos no se tocan. Si la versión nueva no arrancara, se vuelve sola a la anterior.
Desinstalar: el botón Desinstalar… de Inicio quita los accesos directos y abre la carpeta para que la borres. Fuera de esa carpeta no queda nada.

3 Estructura de carpetas

Cuando abras la carpeta del programa verás esta organización:

BOLD-Local-DB/
├── Start BOLD-Local-DB         ← lo único que tienes que abrir
├── guide/            ← esta guía
└── data/             ← todo lo tuyo; las actualizaciones no lo tocan
    ├── raw/          ← el .tar.gz de BOLD que arrastres o selecciones
    ├── processed/    ← archivos intermedios (TSV filtrado)
    ├── exports/      ← copia de lo exportado (se vacía al abrir el visor)
    ├── database/     ← bold_db.db, la base de datos terminada
    └── state/        ← ajustes, selección de campos y registros (logs/)

Hay además dos carpetas ocultas: .program/, con el programa (la sustituyen las actualizaciones), y .runtime/, con el Python y los componentes que descarga el lanzador. Si borras .runtime/, se vuelve a descargar la próxima vez.

✅
No tienes que crear ninguna carpeta a mano. Toda la carpeta data/ se genera automáticamente al abrir el programa. Si vienes de la versión 1.2.0 o anterior, el programa mueve solo la base de datos y los ajustes de la antigua carpeta app/ a data/.

4 Construir la base de datos

Solo necesitas hacer esto una vez. Cuando BOLD publique una versión nueva puedes actualizar la base en lugar de reconstruirla (ver Reanudar y actualizar).

Debajo de cada pantalla está el panel Log, con lo que va ocurriendo. Ver estado vuelve a escribir en qué punto está el proyecto (qué pasos faltan y qué hacer a continuación) y Limpiar vacía el panel sin afectar a los archivos.

Descargar el archivo de BOLD

  1. Desde bench.boldsystems.org/index.php/datapackages/Latest descarga el archivo completo de datos (se requiere de una cuenta en BOLD). Tendrá un nombre similar a BOLD_Public.DIA-MES-AÑO.tar.gz. Puedes dejarlo donde sea (por ejemplo, tu carpeta de Descargas).
  2. Abre BOLD-Local-DB (acceso directo BOLD-Local-DB) y, en la barra lateral, entra en «1. Preparar datos» (sección PASOS INDIVIDUALES).
  3. Arrastra el archivo .tar.gz sobre el recuadro que aparece ahí — o pulsa «Examinar» y selecciónalo. El Constructor lo copia automáticamente a data/raw/; no hace falta moverlo a mano ni crear ninguna carpeta primero.
  4. No descomprimas el archivo; el programa lo hace solo.
ℹ️
Si prefieres copiarlo tú mismo con el explorador de archivos en lugar de usar el recuadro, también funciona: solo tiene que quedar directamente dentro de data/raw/. El recuadro es simplemente un atajo que hace esa copia por ti y evita tener que localizar la carpeta.
⚠️
El .tar.gz se elimina automáticamente. Al terminar el Paso 1, el Constructor borra de data/raw/ tanto el .tar.gz como el TSV sin filtrar, para liberar los 10–15 GB que ocupan una vez ya procesados.

Por eso conviene dejar el original donde lo descargaste (p. ej. Descargas) y que el Constructor solo trabaje con la copia en data/raw/. Si algo falla a mitad del proceso, o quieres reconstruir la base más adelante, vuelves a arrastrarlo sin tener que descargar otra vez esos 10–15 GB desde BOLD.

Si prefieres conservarlo, marca «Conservar el .tar.gz al terminar» en el Paso 1: el paquete se queda en data/raw/ y cambiar la selección de campos más adelante no obliga a descargarlo de nuevo. Puedes borrarlo después con «Liberar espacio» en la pantalla de Inicio.
ℹ️
Mientras el Constructor copia el archivo, lo guarda como .part y todavía no cuenta como entrada del Paso 1; los botones se habilitan cuando la copia termina.
⚠️
Deja un solo archivo .tar.gz en data/raw/. Si hay varios, el Constructor usa el más reciente según la fecha de publicación de su nombre (p. ej. BOLD_Public.02-Oct-2026) e ignora los demás sin borrarlos.

Elegir los campos que se guardan (opcional)

El panel Campos, en la barra lateral del Constructor (sección CONFIGURACIÓN), decide qué columnas del archivo de BOLD terminan en la base de datos. Trae marcadas por defecto las 23 columnas de siempre (ver Campos disponibles), pero puedes activar cualquiera de las 76 que ofrece el paquete público de BOLD — coordenadas de colecta, hábitat, cebadores, institución, etc.

  1. Marca o desmarca los campos que quieras guardar. Los que aparecen con un candado (ID BOLD, ID Muestra, BIN, taxonomía básica, Marcador, Secuencia…) no se pueden quitar: el visor los necesita para funcionar.
  2. Junto a cada campo marcado hay una segunda casilla, "búsqueda rápida": actívala en los campos por los que realmente vayas a buscar (crea un índice en el Paso 3 y los incluye en la búsqueda de texto completo del Paso 4). Déjala apagada en campos que solo quieres ver o exportar — cada índice cuesta espacio en disco.
  3. Pulsa "Guardar selección" para escribirla en data/state/fields_config.json.
ControlQué hace
Restablecer camposVuelve a marcar en la lista los 23 campos de fábrica. Solo cambia lo que ves: no toca el archivo hasta que pulses "Guardar selección".
Comprobar con el TSVRelee la cabecera del archivo descargado y avisa si algún campo configurado ya no existe, o si BOLD añadió campos nuevos que no estás usando. Solo está disponible una vez descomprimido el .tar.gz (durante o después del Paso 1).
⚠️
Cambiar la selección obliga a repetir el Paso 1 con el .tar.gz de BOLD, porque los campos se extraen al filtrar el TSV. El programa detecta el cambio solo y vuelve a filtrar automáticamente si el .tar.gz sigue disponible; si ya se borró (se elimina al terminar el Paso 1, salvo que marcaras «Conservar el .tar.gz al terminar»), tendrás que volver a descargarlo para aplicar la nueva selección.
ℹ️
Si BOLD renombra o retira un campo en una versión nueva, el panel lo marca en rojo ("no está en el TSV") y, si encuentra un nombre parecido en la cabecera nueva, lo sugiere. Un campo que BOLD ofrece y que no tienes activado aparece en ámbar ("nuevo en BOLD"). Si el campo ausente es uno de los que el visor necesita para funcionar, el Paso 1 se detiene con un mensaje explicando cuál falta, en vez de construir una base de datos incompleta.

Opción A — Ejecutar todos los pasos al tiempo (recomendado)

  1. Haz doble clic en el acceso directo BOLD-Local-DB (o en Start BOLD-Local-DB). Se abrirá el programa en la pantalla de Inicio.
  2. Haz clic en «Crear la base de datos», bajo la Opción 1.
  3. Confirma en el diálogo que aparece.
  4. Espera a que finalice. El proceso puede tardar varias horas dependiendo del tamaño del archivo y la velocidad de tu computadora.
✅
Cuando termine verás en el panel de salida: === PROCESO TERMINADO ===, seguido de Todo completo. Pulsa «Abrir el visor» en Inicio.

La Opción 1 ejecuta los pasos 1, 2 y 3. La Opción 2 de la misma pantalla («Crear la base de datos completa») ejecuta los cuatro pasos, incluido el Paso 4 opcional (búsqueda por texto libre); también puedes lanzar el Paso 4 más adelante desde la lista de pasos individuales. La Opción 3 («Actualizar la base de datos») es para después, cuando BOLD publique un paquete nuevo: ver Reanudar y actualizar.

ℹ️
Los botones de Inicio solo se habilitan cuando pueden ejecutarse: con un paquete en la zona de arrastre, o cuando queda algún paso pendiente cuya entrada ya está en disco. Mientras un paso está en marcha permanecen deshabilitados. Pasa el ratón por encima de un botón deshabilitado para ver por qué.

Paso 1 — Preparar datos (obligatorio)

Descomprime el archivo .tar.gz y extrae solo las columnas marcadas en el panel Campos — 23 por defecto, ajustable.

  • Selecciona «1. Preparar datos» en el menú izquierdo → clic en Ejecutar.
  • Duración aproximada: 15–30 minutos.
  • Resultado: un archivo .filt.tsv en data/processed/.
  • Al terminar se borran de data/raw/ el .tar.gz y el TSV sin filtrar, para liberar espacio, salvo que marques «Conservar el .tar.gz al terminar» (la opción se recuerda). Si copiaste el archivo en vez de moverlo, tu descarga original sigue intacta donde estaba.
  • Antes de filtrar, el programa verifica que los campos configurados existan en la cabecera real del archivo descargado — ver panel Campos.
  • Al terminar resume cuántas filas tenía el paquete, cuántas se guardan (las que tienen secuencia) y cuántas se descartan por no tenerla. Si alguna línea del paquete está rota (le faltan columnas) y no se pudo leer, también lo indica.

Paso 2 — Construir base de datos (obligatorio)

Importa los datos filtrados a la base de datos.

  • Selecciona «2. Construir base de datos» → clic en Ejecutar.
  • Duración aproximada: 10–20 minutos.
  • Resultado: el archivo data/database/bold_db.db.
  • Cada fila del paquete de BOLD es una secuencia, no un espécimen: un espécimen secuenciado para varios marcadores (p. ej. COI-5P y 16S, o matK y rbcLa) tiene una fila por marcador con el mismo processid. Se guardan todas, y el registro de actividad indica cuántas son secuencias adicionales de especímenes con más de un marcador.
  • Al terminar, el paso comprueba que se hayan guardado todas las filas que dejó el Paso 1. Si no cuadran, la base nueva se descarta y la actual queda intacta.
  • La base nueva se construye aparte (bold_db.db.building) y solo sustituye a la actual al terminar los pasos, así que el visor puede seguir usando la anterior mientras tanto. Por eso hace falta temporalmente tanto espacio libre como el que ocupa la base actual; el paso avisa si el disco parece pequeño.
⚠️
Bases creadas con versiones anteriores. Hasta ahora el programa guardaba una sola secuencia por espécimen y dejaba fuera unas 400.000 secuencias de otros marcadores. Si tu base es de esa época, el Constructor te avisa: el visor sigue funcionando, pero conviene reconstruirla (Opción 1 o 2) para tenerlas todas, y la actualización (Opción 3) no la acepta hasta entonces. El .filt.tsv actual sirve: no hace falta repetir el Paso 1.

Paso 3 — Acelerar búsquedas (recomendado)

Crea índices para que las búsquedas sean rápidas. Sin este paso la base funciona, pero cada consulta puede tardar minutos en vez de segundos.

  • Selecciona «3. Acelerar búsquedas» → clic en Ejecutar.
  • Duración aproximada: 35–75 minutos.
  • Los índices de los campos que ya no marcas para indexar en el panel Campos se eliminan, y se recupera su espacio en disco.

Paso 4 — Búsqueda por texto libre (opcional)

⚠️
Este paso es opcional. Tarda bastante rato (unos 50–90 minutos según el tamaño de la base y la velocidad del disco) y añade aproximadamente un 25% al tamaño de la base de datos. Puedes detenerlo con Detener en cualquier momento, pero el índice no se guarda a medias: la siguiente vez empieza de nuevo desde el principio. Solo es necesario si quieres usar la pestaña "Búsqueda de texto completo".
  • Selecciona «4. Búsqueda por texto libre» → clic en Ejecutar.
  • Por defecto el índice cubre casi los mismos campos que la búsqueda por campos (19 de 20): ID Muestra, ID Campo, ID Museo, BIN, taxonomía completa (reino a especie), identificación, ID Nivel, país, estado, región, Bases, marcador y fecha de secuencia. Queda fuera código país (ver nota más abajo). Esta lista depende de qué campos hayas marcado como "búsqueda rápida" en el panel Campos; si cambiaste la selección, puede ser distinta.

Reanudar y actualizar

El Constructor detecta el trabajo ya hecho y se salta lo que no hace falta repetir:

  • Si ya existe el TSV filtrado de ese mismo paquete, el Paso 1 se omite.
  • Si la base ya se construyó desde ese mismo TSV, el Paso 2 se omite.
  • Solo se crean los índices que aún faltan.
  • Si el FTS corresponde a los datos actuales, el Paso 4 se omite.

BOLD publica cada semana un paquete completo nuevo. Para pasar a esa versión hay dos caminos; en ambos empiezas igual: coloca el nuevo .tar.gz en data/raw/ (o arrástralo a Inicio).

  • Actualizar (Opción 3 en Inicio): prepara el paquete nuevo (Paso 1), lo compara con la base actual y aplica solo los registros nuevos, modificados y eliminados. Los índices y la búsqueda por texto libre se actualizan a la vez, así que no se repiten los pasos 3 y 4, que son la mayor parte del tiempo de una reconstrucción. No hace falta conservar el .filt.tsv del paquete anterior: la comparación se hace contra la base, que guarda una huella de cada registro, y el Paso 1 borra los archivos de la versión anterior al preparar la nueva. Si lanzas «Actualizar» suelto desde la lista de pasos, ejecuta antes el Paso 1 con el .tar.gz nuevo: la actualización usa el .filt.tsv que hay en data/processed/.
  • Reconstruir (Opción 1 o 2): borra la base y la crea desde cero con el paquete nuevo.

Qué opción conviene depende del equipo y de cuánto haya cambiado:

  • Con disco SSD y RAM suficiente para que quepan los índices (del orden del tamaño de la base de datos o más), actualizar suele tardar una fracción de reconstruir. Inicio muestra la RAM del equipo y el tamaño de la base para que puedas compararlos.
  • En un disco duro mecánico, o con mucha menos RAM que el tamaño de la base, cada cambio cuesta bastante más y la ventaja se reduce: reconstruir puede tardar parecido.
  • Si cambia más del 10 % de los registros, la actualización se detiene sin tocar nada y recomienda reconstruir.
  • Tras muchas actualizaciones, conviene reconstruir de vez en cuando (por ejemplo, una vez al mes): los índices se fragmentan con los cambios.
💡
Si una actualización falla o la detienes, la base de datos queda exactamente como estaba, y el visor puede seguir usándose mientras se actualiza. La actualización necesita una base creada con esta versión del programa (guarda una huella de cada registro); con una base anterior, reconstrúyela una vez. Si cambias la selección de campos, también hay que reconstruir.
⚠️
Si interrumpes un paso con el botón Detener, los archivos parciales se borran para evitar datos corruptos. Al volver a ejecutar, ese paso empieza de nuevo.

5 Consultar la base de datos

Abrir la base de datos

Haz doble clic en el acceso directo Visor BOLD-Local-DB (o pulsa «Abrir el visor» en la pantalla de Inicio del Constructor). Se abrirá una ventana de terminal y, en cuanto el servidor esté listo, el navegador en http://127.0.0.1:5001. Si el visor ya está en marcha, el acceso directo solo vuelve a abrirlo en el navegador.

⚠️
La ventana de terminal debe permanecer abierta mientras uses la base de datos. Si la cierras, el navegador dejará de funcionar y verás el aviso "SIN CONEXIÓN AL SERVIDOR".
ℹ️
El servidor se cierra solo unos segundos después de cerrar la última pestaña del visor. Recargar la página (F5) o tener varias pestañas abiertas no lo detiene. El visor solo lee la base de datos, así que puede seguir abierto mientras el Constructor la actualiza.

Arriba a la derecha de la página aparece la versión de BOLD cargada, y junto al título el número total de registros de la base. Si el paquete de BOLD con el que se construyó tiene más de un mes, junto a la fecha aparece una etiqueta amarilla («hace 50 días»): es un recordatorio de que BOLD ya ha publicado versiones más recientes y puedes actualizar la base.

La pestaña Análisis de secuencias, a la derecha de los modos de búsqueda, se explica en su propia sección: Análisis de secuencias.

Modos de búsqueda

📋 Búsqueda avanzada por campos

Filtra registros combinando condiciones sobre columnas específicas: especie, país, marcador, BIN, etc.

🔍 Búsqueda de texto completo

Busca una o varias palabras en todos los campos de texto a la vez. Requiere haber completado el Paso 4.

📦 Lote en BOLD local

Busca una lista entera de valores cargando un archivo de texto. Ideal para muchas especies o IDs a la vez.

🧬 Lote en GenBank

Busca una lista de términos en NCBI GenBank, en línea. Conteos, metadatos y secuencias por término.

📊 Análisis de secuencias

No es una búsqueda: analiza las secuencias de una búsqueda, de los registros marcados o de un FASTA. Ver sección 6.

Búsqueda avanzada por campos

  1. La primera fila no lleva conector: en su lugar verás la etiqueta Campo.
  2. Elige el campo por el que quieres buscar (ej. Especie, País, BIN).
  3. Elige el operador.
  4. Escribe el valor. Aparecerán sugerencias de autocompletar.
  5. Haz clic en Buscar o presiona Enter.

Para buscar con varias condiciones, haz clic en "+ Añadir condición". El selector AND / OR / NOT de cada nueva fila indica cómo se une esa condición con las anteriores.

ConectorSignificadoEjemplo
ANDAmbas condiciones deben cumplirsePaís = Colombia AND Marcador = COI-5P
ORAl menos una condición debe cumplirseEspecie = Panthera leo OR Especie = Panthera onca
NOTExcluir los que cumplen esa condiciónFamilia = Felidae NOT Género = Felis
ℹ️
No hay paréntesis: como en SQL, AND y NOT se aplican antes que OR. Así, Especie = Panthera leo OR Especie = Panthera onca AND País = Brazil devuelve todos los leones (de cualquier país) más los jaguares de Brasil. Para limitar las dos especies a Brasil, repite la condición en cada rama: Especie = Panthera leo AND País = Brazil OR Especie = Panthera onca AND País = Brazil. Para listas largas, usa el Lote en BOLD local con un segundo campo de filtro.

Búsqueda de texto completo

ℹ️
Disponible solo si completaste el Paso 4 (Búsqueda por texto libre).
  1. Escribe una o varias palabras en el cuadro de búsqueda.
  2. Haz clic en Buscar o presiona Enter.

Por defecto la búsqueda recorre casi los mismos campos que la búsqueda por campos (19 de 20): ID Muestra, ID Campo, ID Museo, BIN, reino, filo, clase, orden, familia, género, especie, identificación, ID Nivel, país, estado, región, Bases, marcador y fecha de secuencia — la lista exacta depende de qué campos marcaste como "búsqueda rápida" en el panel Campos. No busca dentro de la secuencia de ADN, las coordenadas, el ID BOLD (ya tiene su propia búsqueda exacta como identificador único de registro) ni el código país: al ser siempre de 2 letras (ej. "CO", "US"), es demasiado corto para el tipo de índice que usa esta búsqueda — usa el país (nombre completo) o la búsqueda por campos con Código País = ....

Lo que escribesResultado
PantheraRegistros que contienen esa palabra en cualquier campo de texto, incluso como parte de otra palabra (ej. también encuentra "Pantherinae")
Panthera ColombiaAmbas palabras presentes, en cualquier campo, no necesariamente el mismo (equivale a AND)
Panthera AND ColombiaAmbas palabras presentes, en cualquier campo
Panthera OR FelisCualquiera de las dos palabras

ℹ️
Sin comillas, cada palabra se busca por separado en cualquier campo de texto, y todas deben aparecer en el registro (aunque sea en columnas distintas y sin relación entre sí). Esto puede producir coincidencias inesperadas: buscar Ara macao sin comillas también encuentra registros donde "Ara" aparece como fragmento de otra palabra en un campo (ej. el género Hylarana, que contiene "ara") y "macao" coincide por separado con otro campo (ej. una región llamada Macao), aunque el registro no tenga nada que ver con el ave.

Con comillas ("Ara macao") la búsqueda exige que el texto aparezca completo y seguido dentro de un mismo campo, eliminando ese tipo de coincidencias cruzadas — es la forma recomendada de buscar un nombre de especie de dos palabras.
⚠️
Buscar un valor de Bases de solo 1 o 2 dígitos (ej. 34) no encuentra nada, por la misma razón que el código país: el índice no puede representar textos de menos de 3 caracteres. Con 3 dígitos o más (ej. 658) funciona con normalidad.
⚠️
Los conectores AND, OR y NOT deben escribirse en MAYÚSCULAS y con un término a cada lado (Panthera OR busca la palabra «OR»). Los paréntesis agrupan términos cuando están equilibrados; si no, se ignoran. Cualquier otro símbolo (* : . - + / ' | & ! ^) se busca como texto literal, así que valores como Cote d'Ivoire o Peru/Bolivia funcionan tal cual, pero el asterisco no funciona como comodín. Las comas y los puntos y coma separan palabras, igual que los espacios. Dentro de una frase entre comillas, AND/OR/NOT no actúan como conectores: se buscan como palabras literales de la frase.

Lote en BOLD local

Ideal cuando tienes una lista de especies, BINs o IDs y quieres obtener todos sus registros a la vez.

La búsqueda por lote en BOLD local es, en esencia, una búsqueda por campos automatizada: repite la misma consulta una vez por cada término de tu archivo. Eso implica que todos los términos del archivo deben pertenecer a un mismo campo, el que selecciones en Campo 1. El programa no deduce a qué categoría pertenece cada línea: aplica el campo elegido a todas por igual.

⚠️
No mezcles categorías dentro del archivo. Una lista con Panthera leo, COI-5P y Colombia no funciona: son valores de tres campos distintos (Especie, Marcador y País). Si buscas con Campo 1 = Especie, solo Panthera leo arrojará resultados y los otros dos aparecerán en not_found.txt.

Para cruzar dos campos —por ejemplo, esas especies únicamente en ciertos países— no los juntes en un archivo: usa dos archivos separados con la opción "Agregar segundo campo de filtro".

Única excepción: dentro de la taxonomía sí puedes mezclar niveles (familias, géneros y especies en el mismo archivo), porque los términos de una sola palabra se buscan en todos los niveles a la vez. Ver Cómo se interpretan los términos taxonómicos, más abajo.
  1. En Campo 1, selecciona la columna que corresponde a los términos de tu archivo (ej. Especie si el archivo contiene nombres de especies).
  2. Arrastra un archivo .txt o .csv al área indicada (un valor por línea), o haz clic en "examina".
  3. Opcionalmente, activa "Agregar segundo campo de filtro" y carga una segunda lista para restringir por otro campo (ej. esas especies solo en ciertos países).
  4. Si necesitas las secuencias en formato FASTA, marca "Exportar también en formato FASTA".
  5. Opcionalmente, abre "⚙ Personalizar reporte resumen" para añadir columnas al summary.csv (ver Personalizar el reporte resumen).
  6. Haz clic en "Buscar en Batch" y espera; al terminar se descarga un archivo ZIP.

Cómo se interpretan los términos taxonómicos

Si el Campo 1 es taxonómico (reino, filo, clase, orden, familia, género o especie):

  • Un término de una sola palabra (ej. Felidae) se busca en todos los niveles a la vez: reino, clase, orden, familia, género y especie. No hace falta acertar el nivel exacto.
  • Un término de dos palabras (ej. Panthera leo) se busca solo en Especie.
  • Un término de tres palabras (ej. Panthera leo persica) se busca en Subespecie, si la base incluye ese campo indexado; si no, aparece en not_found.txt.
  • Los guiones bajos se convierten en espacios (Panthera_leo = Panthera leo), la primera letra se pone en mayúscula y se descartan los duplicados.

Para cualquier otro campo (BIN, marcador, IDs, país…) la coincidencia es exacta, sin distinguir mayúsculas.

Lote en GenBank

A diferencia de las otras tres pestañas, esta no consulta tu base de datos local: busca en NCBI GenBank (base de datos nucleotide) en línea, así que necesita conexión a internet. Sirve para comparar lo que hay en BOLD con lo depositado en GenBank para la misma lista de especies, o para descargar en bloque secuencias y metadatos de GenBank.

  1. Opcionalmente, pega tu API key de NCBI. Sin ella NCBI permite ~3 peticiones por segundo; con ella, ~10, así que los lotes grandes terminan unas tres veces antes. Se recuerda en el navegador. Puedes obtenerla gratis en los ajustes de tu cuenta de NCBI.
  2. En el Criterio 1, elige el campo de NCBI (Organism, Country, Gene, Title, All Fields, Accession, Author, Journal) y escribe o pega un término por línea, o arrastra un archivo .txt/.csv sobre el cuadro (de un .csv se usa la primera columna).
  3. Opcionalmente, activa "Agregar segundo criterio" y rellénalo igual (ver Cómo se combinan los dos criterios).
  4. Ajusta los registros por consulta (límite) y elige las salidas: el CSV de conteos se genera siempre; Metadatos (TSV) y Secuencias (FASTA) son opcionales.
  5. Opcionalmente, abre "⚙ Personalizar reporte resumen" para añadir columnas a genbank_counts.csv.
  6. Pulsa "Buscar en GenBank". En el panel se ven el progreso, la consulta en curso, el tiempo restante estimado y un registro con el resultado de cada consulta. Al terminar, pulsa "Descargar ZIP".

El contador junto a cada lista muestra el número de términos distintos (los guiones bajos cuentan como espacios y se eliminan duplicados sin distinguir mayúsculas), y junto al botón verás cuántas consultas a NCBI hará la búsqueda.

Cómo se combinan los dos criterios

  • Solo criterio 1: una consulta por término — Panthera onca[Organism].
  • Criterio 2 con un solo valor: actúa como filtro fijo aplicado a todos los términos — Panthera onca[Organism] AND Colombia[Country].
  • Criterio 2 con varios valores: cada término se cruza con cada valor. 50 especies × 3 genes = 150 consultas.

Formato de los archivos FASTA

Cada encabezado combina los datos disponibles del registro, separados por |. Es el mismo en la exportación desde la tabla de resultados y en Lote en BOLD local:

>ID_BOLD|ID_Muestra|BIN|Taxón_más_específico|Marcador
  • El taxón más específico es el primero disponible en este orden: especie, género, familia, orden, clase, filo, reino.
  • Se eliminan los guiones de alineamiento y las N de los extremos.
  • Las secuencias de menos de 50 bases se descartan.
ℹ️
Para archivos grandes la exportación se procesa en segundo plano con una barra de progreso; cuando termina aparece un botón de descarga. Si ningún registro tiene una secuencia utilizable, el diálogo lo indica en lugar de ofrecer un archivo vacío. Mientras se genera, el archivo se guarda en data/exports/ (subcarpetas csv_exports, fasta_exports y batch_exports), donde sigue disponible para volver a descargarlo mientras el visor esté abierto: en cada una se conservan los 20 archivos más recientes, y al abrir el visor de nuevo se vacían.

6 Análisis de secuencias

La pestaña Análisis de secuencias del visor revisa un conjunto de secuencias sin salir del programa ni necesitar internet. Tiene dos niveles:

  • Análisis básico (sin alinear, segundos aunque sean miles de secuencias): composición y calidad, revisión de la traducción (codones de parada), haplotipos por especie y concordancia especie–BIN.
  • Distancias y árbol (bajo demanda, sobre las mismas secuencias): alineamiento, distancias genéticas al estilo de BOLD, barcode gap por especie, árbol neighbour-joining y, si se pide, delimitación de especies con ASAP y ABGD.
  • Red de haplotipos (bajo demanda, de una especie o de todas las secuencias): redes TCS o MSN con estadísticos de diversidad.
⚠️
Cada análisis usa un solo marcador. Longitudes, composición, haplotipos y distancias de genes distintos no se pueden comparar, y el marcador decide si las secuencias se traducen y con qué código genético. Si la entrada mezcla marcadores (p. ej. COI-5P y 16S de los mismos especímenes), la pestaña te pregunta cuál analizar y deja fuera el resto.

Se reconocen la que exporta este visor (processid|sampleid|BIN|taxón|marcador), la de BOLD (processid|taxón|marcador|accesión), un identificador seguido del nombre (>MN123456.1 Carollia perspicillata voucher…, como en GenBank y la mayoría de fuentes) y el nombre unido al identificador (>Carollia_perspicillata_ABC123); con cualquier otra solo se usa la primera palabra como identificador. El país no viaja en ningún FASTA: para el color por país y la geografía de la red, analiza desde la búsqueda. Tras analizar, un aviso bajo la línea Entrada dice cuántas secuencias traían cada dato y qué no estará disponible.

Haplotipos

Agrupa por especie las secuencias idénticas, sin alinear. Como los barcodes de un mismo haplotipo suelen diferir solo en dónde se recortaron, una secuencia contenida en otra más larga cuenta como el mismo haplotipo. Las secuencias con N o bases ambiguas se excluyen (una sola N crearía un haplotipo falso). El botón Red de cada especie construye su red de haplotipos.

ColumnaSignificado

🧪
Ejemplo. Especie A tiene 10 secuencias repartidas en 3 haplotipos de 6, 3 y 1 secuencias. Haplotipos = 3, únicos = 1, y Hd = 10/9 · (1 − (0,6² + 0,3² + 0,1²)) = 1,111 · 0,54 = 0,60.

Cómo leerlo:
  • Hd cercano a 0 con muchas secuencias: población poco diversa, un cuello de botella, o muestras de una sola localidad o del mismo linaje.
  • Hd cercano a 1 y casi todos los haplotipos únicos: mucha diversidad, o un muestreo que aún no ha capturado la variación de la especie (cada secuencia nueva añadiría un haplotipo).
  • Con 2 o 3 secuencias Hd solo puede tomar unos pocos valores y apenas dice nada: compara especies con tamaños de muestra parecidos.

Antes de empezar: distancias y barcode gap

El análisis de distancias responde a una pregunta: ¿el código de barras separa bien las especies de este conjunto? Esta sección explica los conceptos; las siguientes, cada parte del resultado.

Qué es una distancia

Se toman dos secuencias alineadas y se cuenta en qué porcentaje de posiciones difieren:

Secuencia A:  A C G T T A G C A T ...
Secuencia B:  A C G T C A G C G T ...
                      ↑       ↑
              2 diferencias en 10 posiciones = 20 %
  • 0 %: las dos secuencias son idénticas.
  • 2 %: difieren en unas 13 de las 658 bases del COI.
  • 25 %: difieren en una de cada cuatro bases, lo típico entre géneros o familias distintos.

El modelo K2P (el predeterminado) ajusta un poco ese porcentaje: con el tiempo una misma posición puede cambiar más de una vez y esos cambios no se ven, así que K2P los compensa. En la práctica puedes leerlo como «porcentaje de bases distintas».

La idea central: dentro frente a entre especies

Si el barcode funciona, dos individuos de la misma especie suelen diferir menos de un 1–2 %, y dos de especies distintas, más de un 3–5 %:

 Misma especie          Especies distintas
 ███████                            ████████████
 0%  1%  2%  3%  4%  5% ...    10%     20%     30%
        ↑─────── hueco ───────↑
          = "barcode gap"

Ese hueco entre las dos nubes es el barcode gap. Si existe, una secuencia desconocida se puede asignar a su especie sin dudas. Los umbrales del tipo «2 %» son orientativos: varían entre grupos.

El barcode gap de una especie

Para cada especie se calculan dos números:

  • Intra máx.: cuánto difieren las dos secuencias más distintas de esa especie.
  • Vecino: cuánto difiere la secuencia más parecida de otra especie.

Gap = Vecino − Intra máx. Si es positivo, hasta las secuencias más distintas de la especie se parecen más entre sí que a cualquier otra especie: está bien separada. Si es cero o negativo, algo se mezcla.

Ejemplo: un registro mal identificado

Una Especie X tiene 6 secuencias. Cinco son idénticas entre sí y están en un BIN; la sexta está a un ~30 % de ellas, en otro BIN, y es idéntica a una secuencia de una Especie Y de otro género:

  • Intra máx. = 30 %: la sexta secuencia frente a sus «compañeras» de especie.
  • Vecino = 0 %: la sexta secuencia es idéntica a la Especie Y.
  • Gap = 0 − 30 = −30 %.

La especie no está mal delimitada: esa sexta secuencia es casi seguro una Especie Y etiquetada como Especie X (error de identificación o tubo cambiado). Que BOLD la haya puesto en el BIN de la Especie Y lo confirma.

💡
Regla práctica: un gap muy negativo con el vecino a ~0 % casi siempre es un registro mal identificado, no un problema real de la especie. Basta un registro así para disparar el máximo intraespecífico de su especie y hundir el mínimo entre especies del resumen. La revisión automática de identificaciones encuentra estos registros por ti.

Cómo se alinean

Las secuencias se alinean contra una referencia elegida entre ellas (la más larga sin ambigüedades, sin contar el 10 % más largo, para no escoger un gen completo raro entre barcodes), de forma parecida a como BOLD alinea contra su perfil de COI. Cada secuencia se coloca por los fragmentos que comparte con la referencia y solo donde aparece una inserción o deleción se alinea con huecos. Las bases que una secuencia tiene más allá de la referencia, o insertadas respecto a ella, se descartan. El resultado indica qué referencia se usó, cuántas secuencias necesitaron huecos y cuántas se leyeron en la hebra complementaria.

  • Se excluyen las secuencias con codones de parada o caracteres no válidos (probables pseudogenes o contaminación, que distorsionan las distancias) y las de menos de 100 pb.
  • Dos secuencias que comparten menos de 100 posiciones comparables (p. ej. dos fragmentos de extremos opuestos del gen), o tan distintas que el modelo se satura, quedan sin distancia; el resultado indica cuántos pares.
  • Con un marcador no codificante (ITS, 16S, 18S…) el alineamiento contra una referencia es aproximado, porque abundan las inserciones y deleciones: toma las distancias con cautela.
⚠️
Grupos de alineamiento. Un mismo nombre de marcador puede reunir genes distintos (el «16S» de BOLD incluye el 16S bacteriano y el 16S mitocondrial de animales) o taxones demasiado lejanos para alinearse. Las secuencias que no se alinean con la primera referencia forman otro grupo con su propia referencia (hasta 6 grupos de al menos 3 secuencias). Las distancias y los árboles se calculan dentro de cada grupo; el resultado lista los grupos con sus clases o filos principales. Para analizar uno solo, acota la búsqueda por reino, filo o clase.

Para cada especie se comparan dos valores:

  • Intra máx.: la mayor distancia entre dos secuencias de la propia especie (también se muestra la media, Intra media).

Delimitación de especies (MOTU)

Con Delimitar especies marcado, el cálculo de distancias ejecuta además dos métodos de delimitación de especies: ASAP y ABGD. Los dos agrupan las secuencias en MOTU (unidades taxonómicas operativas moleculares) usando solo las distancias, sin mirar los nombres. La pestaña Especies (MOTU) compara esos grupos con las especies y los BINs de los registros. Si hay varios grupos de alineamiento, cada uno se delimita por separado y se elige en Delimitación del grupo.

MétodoCómo agrupaQué muestra la página
ASAP
Puillandre, Brouillet y Achaz 2021		 Une las secuencias con umbrales de distancia crecientes (agrupamiento jerárquico) y evalúa cada partición que resulta con dos criterios: el p-valor, la probabilidad, según un modelo coalescente, de que los grupos que la partición mantiene separados sean en realidad una sola especie, y el ancho relativo del gap en su umbral. La puntuación ASAP es la media de los dos rangos: la más baja es la mejor. Los grupos que se formaron con un p-valor ≤ 0,001 se vuelven a dividir. Las 10 mejores particiones, con su puntuación, número de MOTU, p-valor, ancho del gap y umbral de distancia.
ABGD
Puillandre et al. 2012		 Busca el primer salto (el barcode gap) en las distancias ordenadas, por encima de una distancia intraespecífica máxima previa P, y agrupa las secuencias que están más cerca que ese salto (partición inicial). Después vuelve a buscar un gap dentro de cada grupo (partición recursiva). Se ejecuta para diez valores de P, de 0,1 % a 10 %, y se detiene en el primero que da un solo grupo. Una fila por valor de P, con el gap encontrado y el número de MOTU de las particiones inicial y recursiva.

Con Ver eliges la partición que se compara con los nombres; al abrir la pestaña se muestra la mejor de ASAP. Para cada especie con nombre (los nombres provisionales como «sp.», «cf.», «aff.» o con números no cuentan) se indica su estado:

EstadoSignificaQué puede ser
CoincideTodas sus secuencias forman un MOTU, sin otras especiesEl marcador delimita la especie igual que la taxonomía.
DivididaSus secuencias se reparten en varios MOTUEspecies crípticas, linajes geográficos muy divergentes o identificaciones a revisar.
Comparte MOTUSu MOTU incluye secuencias de otras especiesEspecies recientes, hibridación, sinonimias o identificaciones a revisar.
Dividida y comparteLas dos cosas a la vezCasos complejos: revisa el árbol.

Los recuadros resumen cuántas especies hay en cada estado y cuántos MOTU son idénticos a un BIN (sus registros con BIN comparten uno, y todos los registros de ese BIN están en el MOTU): una forma rápida de ver cuánto coincide la partición con el sistema BIN de BOLD. ⤓ MOTU (CSV) descarga el MOTU de cada secuencia en la partición elegida, y Ver en el árbol abre el árbol coloreado por MOTU (también se puede colapsar por MOTU y mostrarlo en las etiquetas).

Cómo interpretarlo

Al final de la sección, el recuadro Qué dicen estos resultados hace una primera lectura automática: propone la partición por la que empezar (la de ABGD que se repite con más valores de P seguidos, o la mejor de ASAP si ABGD no da ninguna estable), explica la P previa, el gap, el umbral, la puntuación y el p-valor con los valores de tu análisis, dice si los dos métodos coinciden y qué especies se juntan o se dividen. Las filas a las que se refiere quedan marcadas en verde en las tablas, y Ver esta partición la lleva a la tabla de especies. Se puede ocultar con Ocultar, y descargar aparte con ⤓ PDF (desde el diálogo de impresión, con «Guardar como PDF»), ⤓ TXT o ⤓ MD (Markdown), con el marcador, el número de secuencias y el modelo del análisis. Es una orientación con reglas fijas, no un veredicto: lo que sigue explica cómo razonarlo.

⚠️
Las lecturas automáticas pueden equivocarse. Aplican reglas fijas a las distancias y a los nombres de los registros, sin conocer tu grupo taxonómico, el marcador ni la calidad de cada secuencia, así que pueden contener errores o imprecisiones: umbrales que no sirven para tu grupo, nombres mal asignados en BOLD, alineamientos defectuosos o pocas secuencias. Son una orientación para empezar, no un resultado: confirma cada hallazgo revisando los registros, las secuencias y el árbol, y con otras evidencias (morfología, distribución, otros marcadores) antes de usarlo en una identificación, una publicación o una decisión.
  • No hay una partición «correcta»: son hipótesis. La más sólida es la que se repite en los dos métodos: compara la mejor de ASAP con las de ABGD que se mantienen iguales en varios valores de P.
  • En ABGD, los valores de P más bajos y la partición recursiva tienden a dividir de más (separan poblaciones o haplotipos), y los más altos a juntar de más.
  • Una especie dividida en MOTU que siguen la geografía (compruébalo con el árbol coloreado por país) es una candidata a especie críptica; si el MOTU aparte es una sola secuencia, revisa antes la revisión automática y la ficha del registro.
  • Con Máx. por especie muy bajo (1 o 2) apenas hay variación dentro de especie y los métodos ven peor el gap: usa 5 o más, o todas las secuencias si caben.
  • Los MOTU se numeran por tamaño (MOTU 1 es el más grande) dentro de cada partición: el mismo número en dos particiones no es el mismo grupo.
🧪
Ejemplo. Delimitas 464 secuencias COI-5P de ranas venenosas (Dendrobatidae, máximo 10 por especie). La mejor partición de ASAP da 114 MOTU con un umbral de 4,1 %, y ABGD da 120 MOTU iniciales en la mayoría de los valores de P: las dos coinciden a grandes rasgos. Frente a los nombres, 40 de 84 especies coinciden con un MOTU; entre las que comparten MOTU hay varias especies de Andinobates casi idénticas en COI. Colostethus panamansis aparece dividida y compartida: sus secuencias caen en tres MOTU, cada uno con su BIN, y uno de ellos lo comparte con Colostethus panamensis, el mismo nombre escrito de otra forma. Con Ver en el árbol ves dónde caen esos MOTU antes de revisar los especímenes.
ℹ️
ASAP y ABGD están implementados en el propio programa y se comprobaron contra los programas originales: dan las mismas particiones, y los p-valores de ASAP coinciden dentro de la variación de sus simulaciones. Hay dos diferencias, para que el cálculo tarde segundos: ASAP hace como máximo 10.000 simulaciones por partición (el p-valor más pequeño posible es 0,0001), y las particiones con el mismo p-valor comparten rango. Las simulaciones usan una semilla fija: los mismos datos dan siempre el mismo resultado. Con 2.000 secuencias la delimitación puede tardar alrededor de un minuto.

Red de haplotipos

La pestaña Red de haplotipos dibuja cómo se relacionan los haplotipos: cada círculo es un haplotipo, su tamaño es el número de secuencias y cada marca en una línea es una mutación. Se construye bajo demanda: elige en Secuencias una especie (o todas las del análisis), el método y pulsa Construir red. El botón Red de cada fila de la pestaña Haplotipos la construye directamente para esa especie.

MétodoCómo une los haplotiposCuándo usarlo
TCS (por defecto)
Clement, Posada y Crandall 2000		 Parsimonia estadística, tal como la calcula PopART: une los grupos de haplotipos de menor a mayor distancia a través de haplotipos intermedios no muestreados (puntos negros), colocados para que los caminos de la red reproduzcan lo mejor posible las diferencias observadas. Como PopART, une todos los grupos, sin el límite de conexión del 95 %. La red habitual en estudios de barcoding y filogeografía dentro de una especie.
MSN
Bandelt, Forster y Röhl 1999		 Red de expansión mínima: une los haplotipos directamente con el menor número total de mutaciones e incluye todas las alternativas igual de cortas, por eso puede tener ciclos. No añade intermedios. Conjuntos con muchos haplotipos (admite más que TCS) o muy divergentes.

Las secuencias se alinean como para las distancias y se comparan solo en las posiciones que todas tienen completas (A, C, G o T): así un extremo más corto o una N no crea un haplotipo nuevo. Las que cubrirían una región mucho más corta que las demás se excluyen y se avisa. Por eso el número de haplotipos puede no coincidir con el de la pestaña Haplotipos, que no alinea.

Encima de la red aparecen los estadísticos de diversidad de esas secuencias: Hd (diversidad haplotípica), π (diversidad nucleotídica: proporción media de posiciones distintas entre dos secuencias; k es el mismo valor en número de diferencias), los sitios segregantes y la D de Tajima con su p-valor (con la distribución beta de Tajima, 1989; se aparta de lo esperado en una población de tamaño constante si p < 0.05).

8 Preguntas frecuentes

¿Cuánto espacio en disco necesito?
El archivo .tar.gz de BOLD pesa aproximadamente 10–15 GB. La base de datos SQLite resultante ocupa entre 20 y 30 GB. El índice FTS (Paso 4, opcional) añade en torno a un 25% más sobre ese tamaño. Se recomiendan al menos 80 GB libres. Ten en cuenta que durante el Paso 1 conviven temporalmente el .tar.gz, el TSV extraído y el TSV filtrado.
¿Tengo que crear alguna carpeta antes de construir la base?
No. El programa crea data/ y todo lo que contiene al abrirse. Tú solo tienes que arrastrar el .tar.gz a la pantalla Inicio (o dejarlo en data/raw/).
¿Puedo cerrar el Constructor mientras procesa?
Cerrar la ventana detiene el proceso. El Constructor pregunta antes y, si confirmas, detiene el paso en curso de forma segura y se cierra solo unos segundos después (no lo corta a medias, lo que podría dañar la base de datos). Vuelve a abrirlo y ejecuta el paso de nuevo; el programa detecta el progreso previo y retoma desde donde corresponde. Cambiar el idioma con un paso en marcha se guarda, pero solo se aplica la próxima vez que abras el Constructor.
El navegador dice "SIN CONEXIÓN AL SERVIDOR".
Significa que el servidor ya no está en marcha: se cerró su ventana de terminal, o se cerró solo tras cerrar la última pestaña del visor. Vuelve a abrir el acceso directo Visor BOLD-Local-DB.
La pestaña "Búsqueda de texto completo" no devuelve nada.
Requiere el Paso 4 (Búsqueda por texto libre). Si no lo ejecutaste, usa la búsqueda por campos, que funciona siempre.
Busqué Panthera leo sin comillas en texto completo y me devolvió resultados de más.
Sin comillas, cada palabra se busca por separado en cualquier campo (equivale a Panthera AND leo), así que un registro puede colarse si contiene "Panthera" en un campo y "leo" en otro sin relación entre sí. Usa comillas — "Panthera leo" — para exigir esa secuencia exacta y contigua dentro de un mismo campo.
Las búsquedas tardan mucho.
Verifica que ejecutaste el Paso 3 (Acelerar búsquedas). Además, los operadores Contiene, No contiene y Termina con no pueden aprovechar los índices; cuando sea posible prefiere Es igual a o Comienza con.
¿Dónde quedan los archivos que exporto?
Se descargan por el navegador a tu carpeta de descargas habitual. Mientras el visor está abierto queda además una copia en data/exports/ (los 20 archivos más recientes de cada tipo), que se borra la próxima vez que lo abres: guarda lo que necesites desde tu carpeta de descargas. ¿Puedo agregar o quitar campos de la base de datos?
Sí, desde el panel Campos del Constructor — ver Elegir los campos. Puedes activar cualquiera de las 76 columnas del paquete público de BOLD, no solo las 23 de fábrica. Un puñado de campos (ID BOLD, ID Muestra, BIN, taxonomía básica, Marcador, Secuencia) no se pueden quitar porque el visor los necesita para funcionar.
Cambié la selección de campos, guardé, pero el visor sigue mostrando lo mismo.
Guardar la selección solo actualiza data/state/fields_config.json; la base de datos no cambia hasta que repites el Paso 1 con el .tar.gz de BOLD (el programa detecta el cambio y vuelve a filtrar solo). Si ya se borró el .tar.gz, tendrás que descargarlo de nuevo; para evitarlo la próxima vez, marca «Conservar el .tar.gz al terminar» en el Paso 1.
¿Con qué frecuencia debo actualizar la base de datos?
BOLD publica nuevas versiones semanalmente. Para actualizar, descarga el nuevo .tar.gz, arrástralo a la pantalla de Inicio (o colócalo en data/raw/) y elige la Opción 3 · Actualizar la base de datos: solo se aplica lo que ha cambiado. Reconstruir con la Opción 1 o 2 también sirve y conviene hacerlo de vez en cuando; ver Reanudar y actualizar.
¿Puedo tener la base de datos en un disco externo?
Sí. Copia toda la carpeta del programa al disco externo y ábrelo desde allí: los accesos directos que hubieras creado se rehacen solos para apuntar a la nueva ubicación.
¿Qué hago si el Paso 1 dice "Entrada no encontrada" aunque puse el archivo?
Verifica que el archivo esté directamente dentro de data/raw/ y que su extensión sea .tar.gz (no .tar ni .gz solo). El programa busca exactamente ese formato. Si el Constructor todavía lo está copiando (aparece como .part), espera a que termine la copia.
Algo falló y el mensaje no me dice lo suficiente.
Abre data/state/logs/error.log: contiene el detalle técnico del último error. El historial completo de cada sesión está en data/state/logs/run_*.log.
Al pulsar «Analizar» me pide elegir un marcador.
La entrada tiene secuencias de varios marcadores (o un FASTA cuyas cabeceras no lo indican) y cada análisis usa uno solo. Elige el marcador en la lista, que muestra cuántas secuencias hay de cada uno, y pulsa Analizar de nuevo; las de otros marcadores quedan fuera. Ver Entrada y opciones.
El resumen de distancias da un máximo dentro de especie altísimo (20–30 %) o un mínimo de 0 % entre géneros.
Casi siempre es uno o pocos registros mal identificados: una secuencia de otra especie con el nombre equivocado infla el máximo de su especie y hunde el mínimo entre especies. La revisión automática de identificaciones, al principio de la pestaña Distancias, los lista con la especie con la que se confunden. Ver también Antes de empezar: distancias y barcode gap.
Las distancias dicen que hay demasiadas secuencias.
El cálculo de distancias admite hasta 5.000 secuencias (1.000 en marcadores no codificantes) y el árbol 2.000. Usa Máx. por especie para quedarte con unas pocas secuencias por especie, o acota la búsqueda (por género, país, etc.). Ver Descargas y límites.
