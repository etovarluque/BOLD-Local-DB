BOLD DB
Installation and usage instructions — Local BOLD database
Windows · macOS · Linux 🌐 Versión en español

1 What is it for?

This tool takes the public records of BOLD (Barcode of Life Data System) and turns them into a local database you can query from your browser, with no internet needed once it's set up.

It has two parts, used in this order:

PartWhat it doesHow to open it
BOLD-Local-DB Processes the file downloaded from BOLD and builds or updates the database The BOLD-Local-DB shortcut, or Start BOLD-Local-DB in the program folder
Web viewer Searches, analyses and exports records once the database is built The BOLD-Local-DB Viewer shortcut, or Open the viewer on Start
ℹ️
The shortcuts are made from the Start screen (on the desktop, in the menu or both). If you move the program folder to another drive, they're remade the next time you open it.

2 Installation

  1. Download the zip for your system from the project's Releases page on GitHub (BOLD-Local-DB-windows.zip, -macos.zip or -linux.zip) and unpack it wherever you like.
  2. Open Start BOLD-Local-DB in the unpacked folder (.bat on Windows, .command on macOS, .sh on Linux).
  3. The first time it downloads its own Python and the components it needs (about 150 MB, once). Then the program opens and offers to create the shortcuts.

There's no need to install Python or anything else: everything stays inside the program folder. You also need:

  • Disk space: at least 80 GB free (see the FAQ).
  • Internet the first time you open the program, to download from BOLD and for the GenBank batch.
ℹ️
macOS: the first time, macOS blocks the downloaded file. Right-click Start BOLD-Local-DB.command → Open → Open. Only once.
Linux: if double-clicking the .sh opens it in a text editor, allow running executable files in your file manager or open it from a terminal.
✅
Updating the program: when a new version is out, the Start screen says so. The Update button downloads it and restarts the program with it; your database and files are not touched. If the new version failed to start, it goes back to the previous one by itself.
Uninstalling: Uninstall… on Start removes the shortcuts and opens the folder for you to delete it. Nothing is left outside that folder.

3 Folder structure

When you open the program folder you'll see this layout:

BOLD-Local-DB/
├── Start BOLD-Local-DB         ← the only thing you need to open
├── guide/            ← this guide
└── data/             ← everything that's yours; updates never touch it
    ├── raw/          ← BOLD's .tar.gz, dropped or selected
    ├── processed/    ← intermediate files (filtered TSV)
    ├── exports/      ← a copy of everything you export
    ├── database/     ← bold_db.db, the finished database
    └── state/        ← settings, field selection and logs (logs/)

There are also two hidden folders: .program/, with the program (updates replace it), and .runtime/, with the Python and components the launcher downloads. If you delete .runtime/, it's downloaded again next time.

✅
You don't have to create any folder by hand. The whole data/ folder is created when the program opens. Coming from version 1.2.0 or earlier, the program moves the database and settings from the old app/ folder into data/ by itself.

4 Building the database

You only need to do this once. When BOLD publishes a new version you can update the database instead of rebuilding it (see Resuming and updating).

Download the file from BOLD

  1. From bench.boldsystems.org/index.php/datapackages/Latest download the complete data file (a BOLD account is required). It will have a name similar to BOLD_Public.DAY-MONTH-YEAR.tar.gz. You can leave it wherever it lands (e.g. your Downloads folder).
  2. Open BOLD-Local-DB (the BOLD-Local-DB shortcut) and, in the sidebar, go to "1. Prepare data" (INDIVIDUAL STEPS section).
  3. Drag the .tar.gz file onto the box shown there — or click "Browse" and select it. The Creator copies it automatically into data/raw/; you don't need to move it by hand or create any folder first.
  4. Don't extract the file; the program does that on its own.
ℹ️
If you'd rather copy it yourself with the file explorer instead of using the box, that also works: it just has to end up directly inside data/raw/. The box is simply a shortcut that does that copy for you and saves you locating the folder.
⚠️
The .tar.gz is deleted automatically. When Step 1 finishes, the Creator deletes from data/raw/ both the .tar.gz and the unfiltered TSV, to free up the 10–15 GB they take up once processed.

That's why it's best to leave the original where you downloaded it (e.g. Downloads) and let the Creator work only with the copy in data/raw/. If something fails partway through, or you want to rebuild the database later, you can just drag it in again instead of having to download those 10–15 GB from BOLD a second time.

If you'd rather keep it, tick "Keep the .tar.gz when done" in Step 1: the package stays in data/raw/, so changing the field selection later doesn't require downloading it again. You can delete it afterwards with "Free up space" on the Start screen.
ℹ️
While the Creator is copying the file, it's saved as .part and doesn't count as Step 1's input yet; the buttons are enabled once the copy has finished.
⚠️
Leave only one .tar.gz file in data/raw/. If there are several, the Creator uses the most recent one, judging by the release date in its name (e.g. BOLD_Public.02-Oct-2026), and ignores the rest without deleting them.

Choosing which fields are saved (optional)

The Field Selection panel, in the Creator's sidebar (SETTINGS section), decides which columns from the BOLD file end up in the database. By default it has the usual 23 columns checked (see Available fields), but you can enable any of the 76 columns offered by BOLD's public data package — collection coordinates, habitat, primers, institution, etc.

  1. Check or uncheck the fields you want to keep. The ones shown with a lock icon (BOLD ID, Sample ID, BIN, basic taxonomy, Marker, Sequence…) can't be removed: the viewer needs them to work.
  2. Next to each checked field there's a second checkbox, "index": turn it on for fields you're actually going to search by (it creates an index in Step 3 and includes the field in Step 4's full-text search). Leave it off for fields you only want to view or export — every index costs disk space.
  3. Click "Save selection" to write it to data/state/fields_config.json.
ControlWhat it does
Reset fieldsRe-checks the 23 factory-default fields in the list. It only changes what you see: it doesn't touch the file until you click "Save selection".
Check against TSVRe-reads the header of the downloaded file and warns if any configured field no longer exists, or if BOLD added new fields you aren't using. Only available once the .tar.gz has been extracted (during or after Step 1).
⚠️
Changing the selection means Step 1 has to be repeated with BOLD's .tar.gz, because fields are extracted while filtering the TSV. The program detects the change on its own and re-filters automatically if the .tar.gz is still available; if it was already deleted (it's removed once Step 1 finishes, unless you ticked "Keep the .tar.gz when done"), you'll need to download it again to apply the new selection.
ℹ️
If BOLD renames or drops a field in a new version, the panel flags it in red ("not in the TSV") and, if it finds a similar name in the new header, suggests it. A field BOLD offers that you don't have enabled shows up in amber ("new in BOLD"). If the missing field is one the viewer needs to work, Step 1 stops with a message explaining which one is missing, instead of building an incomplete database.

Option A — Run all the steps at once (recommended)

  1. Double-click the BOLD-Local-DB shortcut (or Start BOLD-Local-DB). The program will open on the Start screen.
  2. Click "Create the database", under Option 1.
  3. Confirm in the dialog that appears.
  4. Wait for it to finish. The process can take several hours depending on the file size and your computer's speed.
✅
When it finishes you'll see in the output panel: === PROCESS FINISHED ===, followed by All done. Click «Open the viewer» on Start.

Option 1 runs steps 1, 2 and 3. Option 2 on the same screen ("Create the full database") runs all four steps, including the optional Step 4 (FTS); you can also run Step 4 on its own later from the individual step list. Option 3 ("Update the database") is for later, when BOLD publishes a new package: see Resuming and updating.

ℹ️
The Start screen buttons are enabled only when they can run: with a package in the drop zone, or when some step is still pending and its input is already on disk. While a step is running they stay disabled. Hover over a disabled button to see why.

Step 1 — Prepare data (required)

Extracts the .tar.gz file and keeps only the columns checked in the Field Selection panel — 23 by default, adjustable.

  • Select "1. Prepare data" in the left-hand menu → click Run.
  • Approximate duration: 15–30 minutes.
  • Result: a .filt.tsv file in data/processed/.
  • When it finishes, the .tar.gz and the unfiltered TSV are deleted from data/raw/ to free up space, unless you tick "Keep the .tar.gz when done" (the option is remembered). If you copied the file instead of moving it, your original download is still intact where it was.
  • Before filtering, the program checks that the configured fields exist in the actual header of the downloaded file — see the Field Selection panel.
  • When it finishes it reports how many rows the package had, how many are kept (those with a sequence) and how many are left out for having none. If any line of the package is broken (missing columns) and couldn't be read, it says so too.

Step 2 — Build database (required)

Imports the filtered data into the database.

  • Select "2. Build database" → click Run.
  • Approximate duration: 10–20 minutes.
  • Result: the data/database/bold_db.db file.
  • Each row of a BOLD package is a sequence, not a specimen: a specimen sequenced for several markers (e.g. COI-5P and 16S, or matK and rbcLa) has one row per marker under the same processid. All of them are stored, and the log says how many are additional sequences of specimens with more than one marker.
  • When it finishes, the step checks that every row Step 1 kept was stored. If the counts don't match, the new database is discarded and the current one is left as it was.
  • The new database is built separately (bold_db.db.building) and replaces the current one only when the steps finish, so the viewer can keep using the previous one meanwhile. That's why it temporarily needs as much free space as the current database takes; the step warns when the disk looks too small.
⚠️
Databases built by earlier versions. Until now the program kept a single sequence per specimen and left out about 400,000 sequences of other markers. If your database dates from then, the Creator warns you: the viewer still works, but you should rebuild it (Option 1 or 2) to get them all, and the update (Option 3) refuses it until you do. The current .filt.tsv can be reused: Step 1 doesn't need repeating.

Step 3 — Speed up searches (recommended)

Creates indexes so searches are fast. Without this step the database still works, but every query can take minutes instead of seconds.

  • Select "3. Speed up searches" → click Run.
  • Approximate duration: 35–75 minutes.
  • The indexes of fields you no longer mark as "index" in the Field Selection panel are dropped, giving back their disk space.

Step 4 — Full-text search (optional)

⚠️
This step is optional. It takes a long time (roughly 50–90 minutes depending on the database size and disk speed) and adds about 25% to the size of the database. You can stop it with Stop at any time, but the index isn't saved half-built: the next run starts it over from the beginning. It's only needed if you want to use the "Full-text search" tab.
  • Select "4. Full-text search" → click Run.
  • By default the index covers nearly the same fields as the field search (19 of 20): Sample ID, Field ID, Museum ID, BIN, full taxonomy (kingdom to species), identification, ID Rank, country, state, region, Base Count, marker and sequence date. Country code is left out (see the note below). This list depends on which fields you marked as "index" in the Field Selection panel; if you changed the selection, it may differ.

Resuming and updating

The Creator detects work already done and skips whatever doesn't need repeating:

  • If the filtered TSV already exists, Step 1 is skipped.
  • If the database was already built from that same TSV, Step 2 is skipped.
  • Only the indexes that are still missing get created.
  • If the FTS index matches the current data, Step 4 is skipped.

BOLD publishes a new full package every week. There are two ways to move to it; both start the same way: place the new .tar.gz in data/raw/ (or drop it on the Start screen).

  • Update (Option 3 on Start): prepares the new package (Step 1), compares it with the current database and applies only the records that are new, modified or removed. Indexes and full-text search are updated along the way, so Steps 3 and 4, most of a rebuild's time, aren't repeated.
  • Rebuild (Option 1 or 2): deletes the database and creates it from scratch with the new package.

Which one pays off depends on the computer and on how much changed:

  • With an SSD and enough RAM for the indexes to fit (around the size of the database or more), updating usually takes a fraction of a rebuild. Start shows the computer's RAM and the database size so you can compare them.
  • On a mechanical hard disk, or with much less RAM than the database size, each change costs considerably more and the advantage shrinks: a rebuild may take about as long.
  • If more than 10 % of the records changed, the update stops without touching anything and recommends a rebuild.
  • After many updates, rebuild now and then (e.g. once a month): the indexes get fragmented by the changes.
💡
If an update fails or you stop it, the database stays exactly as it was, and the viewer can still be used while it runs. Updating needs a database built with this version of the program (it stores a fingerprint of every record); with an older one, rebuild it once. Changing the field selection also requires a rebuild.
⚠️
If you interrupt a step with the Stop button, the partial files are deleted to avoid corrupted data. Running it again starts that step over from the beginning.

5 Querying the database

Opening the database

Double-click the BOLD-Local-DB Viewer shortcut (or click "Open the viewer" on the Creator's Start screen). A terminal window will open and your browser will open at http://127.0.0.1:5001 as soon as the server is ready. If the viewer is already running, the shortcut just opens it in the browser again.

⚠️
The terminal window must stay open while you use the database. If you close it, the browser will stop working and you'll see the "SERVER DISCONNECTED" notice.
ℹ️
The server closes by itself a few seconds after you close the last viewer tab. Reloading the page (F5) or having several tabs open doesn't stop it. The viewer only reads the database, so it can stay open while the Creator updates it.

In the top right of the page you'll see the loaded BOLD version, and next to the title the database's total record count. If the BOLD package it was built from is over a month old, a yellow badge appears next to the date ("50 days old"): a reminder that BOLD has published newer versions and you can update the database.

The Sequence analysis tab, to the right of the search modes, has a section of its own: Sequence analysis.

Search modes

📋 Advanced field search

Filters records by combining conditions on specific columns: species, country, marker, BIN, etc.

🔍 Full-text search

Searches one or more words across all text fields at once. Requires Step 4 to have been completed.

📦 Local BOLD batch

Searches a whole list of values by uploading a text file. Ideal for many species or IDs at once.

🧬 GenBank batch

Searches a list of terms in NCBI GenBank, online. Record counts, metadata and sequences per term.

📊 Sequence analysis

Not a search: analyses the sequences of a search, of the checked records or of a FASTA file. See section 6.

Advanced field search

  1. The first row has no connector: in its place you'll see the label Field.
  2. Choose the field you want to search by (e.g. Species, Country, BIN).
  3. Choose the operator.
  4. Type the value. Autocomplete suggestions will appear.
  5. Click Search or press Enter.

To search with several conditions, click "+ Add condition". The AND / OR / NOT selector on each new row indicates how that condition joins with the previous ones.

ConnectorMeaningExample
ANDBoth conditions must be trueCountry = Colombia AND Marker = COI-5P
ORAt least one condition must be trueSpecies = Panthera leo OR Species = Panthera onca
NOTExclude records that match that conditionFamily = Felidae NOT Genus = Felis
ℹ️
There are no parentheses: as in SQL, AND and NOT apply before OR. So Species = Panthera leo OR Species = Panthera onca AND Country = Brazil returns every lion (from any country) plus the jaguars from Brazil. To limit both species to Brazil, repeat the condition in each branch: Species = Panthera leo AND Country = Brazil OR Species = Panthera onca AND Country = Brazil. For long lists, use the Local BOLD batch with a second filter field.

Full-text search

ℹ️
Available only if you completed Step 4 (Full-text search).
  1. Type one or more words in the search box.
  2. Click Search or press Enter.

By default the search covers nearly the same fields as the field search (19 of 20): Sample ID, Field ID, Museum ID, BIN, kingdom, phylum, class, order, family, genus, species, identification, ID Rank, country, state, region, Base Count, marker and sequence date — the exact list depends on which fields you marked as "index" in the Field Selection panel. It does not search inside the DNA sequence, the coordinates, the BOLD ID (which already has its own exact search as the record's unique identifier), or the country code: since it's always 2 letters (e.g. "CO", "US"), it's too short for the type of index this search uses — use country (full name) or the field search with Country Code = ... instead.

What you typeResult
PantheraRecords containing that word in any text field, even as part of another word (e.g. it also finds "Pantherinae")
Panthera ColombiaBoth words present, in any field, not necessarily the same one (equivalent to AND)
Panthera AND ColombiaBoth words present, in any field
Panthera OR FelisEither of the two words
Panthera NOT leoPanthera but not leo
(Panthera OR Felis) AND ColombiaParentheses group conditions
"Ara macao"Exact phrase: searches for that complete, contiguous sequence of text within the same field
MexicoAlso finds México: accents are ignored
ℹ️
Without quotes, each word is searched separately in any text field, and all of them must appear in the record (even if in different, unrelated columns). This can produce unexpected matches: searching Ara macao without quotes also finds records where "Ara" appears as a fragment of another word in one field (e.g. the genus Hylarana, which contains "ara") and "macao" separately matches another field (e.g. a region called Macao), even though the record has nothing to do with the bird.

With quotes ("Ara macao") the search requires the text to appear whole and contiguous within the same field, eliminating that kind of cross-field match — it's the recommended way to search for a two-word species name.
⚠️
Searching for a Base Count value with only 1 or 2 digits (e.g. 34) finds nothing, for the same reason as the country code: the index can't represent text shorter than 3 characters. With 3 digits or more (e.g. 658) it works normally.
⚠️
The connectors AND, OR and NOT must be written in UPPERCASE, with a term on each side (Panthera OR searches the word "OR"). Parentheses group terms when they're balanced; otherwise they're ignored. Any other symbol (* : . - + / ' | & ! ^) is searched as literal text, so values like Cote d'Ivoire or Peru/Bolivia work as typed, but the asterisk doesn't work as a wildcard. Commas and semicolons separate words, like spaces. Inside a quoted phrase, AND/OR/NOT don't act as connectors: they're searched as literal words of the phrase.

Local BOLD batch

Ideal when you have a list of species, BINs, or IDs and want to get all their records at once.

A local BOLD batch search is, in essence, an automated field search: it repeats the same query once for each term in your file. That means all the terms in the file must belong to the same field, the one you pick in Field 1. The program doesn't infer which category each line belongs to: it applies the chosen field to all of them alike.

⚠️
Don't mix categories within the file. A list with Panthera leo, COI-5P, and Colombia won't work: those are values of three different fields (Species, Marker, and Country). If you search with Field 1 = Species, only Panthera leo will return results and the other two will show up in not_found.txt.

To cross two fields — for example, those species only in certain countries — don't combine them in one file: use two separate files with the "Add a second filter field" option.

One exception: within taxonomy you can mix levels (families, genera and species in the same file), because single-word terms are searched across all levels at once. See How taxonomic terms are interpreted, below.
  1. In Field 1, select the column that matches the terms in your file (e.g. Species if the file contains species names).
  2. Drag a .txt or .csv file onto the indicated area (one value per line), or click "browse".
  3. Optionally, enable "Add a second filter field" and upload a second list to narrow the results by another field (e.g. those species only in certain countries).
  4. If you need the sequences in FASTA format, check "Also export in FASTA format".
  5. Optionally, open "⚙ Customize summary report" to add columns to summary.csv (see Customizing the summary report).
  6. Click "Run Batch Search" and wait; a ZIP file is downloaded when it finishes.

How taxonomic terms are interpreted

If Field 1 is a taxonomic field (kingdom, phylum, class, order, family, genus, or species):

  • A single-word term (e.g. Felidae) is searched across all levels at once: kingdom, class, order, family, genus, and species. You don't need to get the exact level right.
  • A two-word term (e.g. Panthera leo) is only searched in Species.
  • A three-word term (e.g. Panthera leo persica) is searched in Subspecies, if the database includes that field indexed; otherwise it goes to not_found.txt.
  • Underscores are converted to spaces (Panthera_leo = Panthera leo), the first letter is capitalized, and duplicates are dropped.

For any other field (BIN, marker, IDs, country…) the match is exact, case-insensitive.

The viewer's Sequence analysis tab checks a set of sequences without leaving the program or needing internet. It works at two levels:

Before you start: distances and the barcode gap

The distance analysis answers one question: does the barcode tell apart the species in this set? This section explains the ideas; the next ones, each part of the result.

What a distance is

Take two aligned sequences and count the share of positions where they differ:

Sequence A:  A C G T T A G C A T ...
Sequence B:  A C G T C A G C G T ...
                     ↑       ↑
             2 differences in 10 positions = 20 %
  • 0 %: the two sequences are identical.
  • 2 %: they differ at about 13 of COI's 658 bases.
  • 25 %: they differ at one base in four, typical between genera or families.

The K2P model (the default) adjusts that percentage a little: over time a position can change more than once, and those changes can't be seen, so K2P makes up for them. In practice you can read it as "percentage of different bases".

The core idea: within against between species

When the barcode works, two individuals of the same species usually differ by less than 1–2 %, and two of different species by more than 3–5 %:

 Same species           Different species
 ███████                            ████████████
 0%  1%  2%  3%  4%  5% ...    10%     20%     30%
        ↑──────── gap ────────↑
          = "barcode gap"

That empty stretch between the two clouds is the barcode gap. When it exists, an unknown sequence can be assigned to its species without doubt. Thresholds such as "2 %" are rough guides: they vary between groups.

A species' barcode gap

Two figures are worked out for each species:

  • Max intra: how much the two most different sequences of the species differ.
  • Neighbour: how much the closest sequence of another species differs.

Gap = Neighbour − Max intra. When it is positive, even the species' most different sequences are closer to each other than to any other species: it is well separated. When it is zero or negative, something is mixed up.

Example: a misidentified record

Species X has 6 sequences. Five are identical to each other and share a BIN; the sixth is ~30 % away from them, in another BIN, and identical to a sequence of Species Y, of another genus:

  • Max intra = 30 %: the sixth sequence against its "fellow" sequences.
  • Neighbour = 0 %: the sixth sequence is identical to Species Y.
  • Gap = 0 − 30 = −30 %.

The species is not badly delimited: that sixth sequence is almost surely a Species Y filed as Species X (a misidentification or a swapped tube). BOLD placing it in Species Y's BIN confirms it.

💡
Rule of thumb: a very negative gap with the neighbour at ~0 % is nearly always one misidentified record, not a real problem with the species. One such record is enough to inflate its species' largest intraspecific distance and sink the smallest distance between species in the summary. The automatic identification check finds these records for you.

How they're aligned

Sequences are aligned to a reference picked from among them (the longest one without ambiguities, leaving out the longest 10 %, so as not to pick a rare full gene among barcodes), much as BOLD aligns against its COI profile. Each sequence is placed by the stretches it shares with the reference, and only where an insertion or deletion shows is it aligned with gaps. Bases a sequence has beyond the reference, or inserted relative to it, are dropped. The result says which reference was used, how many sequences needed gaps and how many were read on the reverse strand.

  • Sequences with stop codons or invalid characters (probable pseudogenes or contamination, which distort distances) and those under 100 bp are left out.
  • Two sequences sharing fewer than 100 comparable positions (e.g. two fragments from opposite ends of the gene), or so different that the model saturates, get no distance; the result says how many pairs.
  • With a non-coding marker (ITS, 16S, 18S…) aligning to a reference is approximate, because insertions and deletions are common: take the distances with caution.

Species delimitation (MOTUs)

With Delimit species ticked, the distance analysis also runs two species delimitation methods: ASAP and ABGD. Both group the sequences into MOTUs (molecular operational taxonomic units) from the distances alone, without looking at the names. The Species (MOTUs) tab compares those groups with the records' species and BINs. When there are several alignment groups, each one is delimited apart and chosen in Delimitation of group.

MethodHow it groupsWhat the page shows
ASAP
Puillandre, Brouillet & Achaz 2021		 Joins the sequences at increasing distance thresholds (hierarchical clustering) and scores every resulting partition on two criteria: the p-value, the probability under a coalescent model that the groups the partition keeps apart are really one species, and the relative gap width at its threshold. The ASAP score is the mean of the two ranks: the lowest is the best. Groups formed with a p-value ≤ 0.001 are split again. The 10 best partitions, with their score, number of MOTUs, p-value, gap width and distance threshold.
ABGD
Puillandre et al. 2012		 Looks for the first jump (the barcode gap) in the sorted distances beyond a prior maximum intraspecific distance P, and groups the sequences closer than that jump (initial partition). Then it looks for a gap again within each group (recursive partition). It runs for ten values of P, from 0.1 % to 10 %, and stops at the first one that gives a single group. One row per value of P, with the gap found and the number of MOTUs of the initial and recursive partitions.

Show picks the partition compared with the names; the tab opens on ASAP's best. Each named species (provisional names such as "sp.", "cf.", "aff." or with numbers don't count) gets a status:

StatusMeansWhat it may be
MatchAll its sequences form one MOTU, with no other speciesThe marker delimits the species as taxonomy does.
SplitIts sequences fall into several MOTUsCryptic species, deeply divergent geographic lineages or identifications to check.
Shares MOTUIts MOTU holds sequences of other speciesRecent species, hybridisation, synonyms or identifications to check.
Split and sharesBoth at onceComplex cases: look at the tree.

The tiles count the species in each status and the MOTUs identical to a BIN (their records with a BIN share one, and all of that BIN's records are in the MOTU): a quick measure of how far the partition agrees with BOLD's BIN system. ⤓ MOTUs (CSV) downloads each sequence's MOTU in the partition chosen, and Show on the tree opens the tree coloured by MOTU (it can also be collapsed by MOTU and show it in the labels).

How to read it

  • There is no "right" partition: they are hypotheses. The soundest is the one both methods agree on: compare ASAP's best with the ABGD partitions that stay the same over several values of P.
  • In ABGD, low values of P and the recursive partition tend to over-split (they separate populations or haplotypes), and high ones to lump.
  • A species split into MOTUs that follow geography (check with the tree coloured by country) is a cryptic species candidate; if the separate MOTU is a single sequence, look first at the identification check and the record's card.
  • With a very low Max. per species (1 or 2) there is hardly any variation within species and the methods see the gap less well: use 5 or more, or every sequence if they fit.
  • MOTUs are numbered by size (MOTU 1 is the largest) within each partition: the same number in two partitions is not the same group.
🧪
Example. You delimit 464 COI-5P sequences of poison frogs (Dendrobatidae, at most 10 per species). ASAP's best partition gives 114 MOTUs at a 4.1 % threshold, and ABGD gives 120 initial MOTUs at most values of P: the two broadly agree. Against the names, 40 of 84 species match a MOTU; among those that share a MOTU are several Andinobates species nearly identical in COI. Colostethus panamansis comes out split and shares: its sequences fall into three MOTUs, each with its own BIN, and one of them is shared with Colostethus panamensis, the same name spelt differently. Show on the tree shows where those MOTUs fall before you check the specimens.
ℹ️
ASAP and ABGD are implemented in the program itself and were checked against the original programs: they give the same partitions, and ASAP's p-values agree within the variation of its simulations. There are two differences, so that the run takes seconds: ASAP runs at most 10,000 simulations per partition (the smallest possible p-value is 0.0001), and partitions with the same p-value share their rank. The simulations use a fixed seed: the same data always give the same result. With 2,000 sequences the delimitation may take about a minute.

NJ tree

A neighbour-joining tree built on the computed distances and rooted at the midpoint (halfway along the path between the two most distant sequences). With several alignment groups, pick the group in Tree of group. Sequences lacking a distance to some other one are taken out of the tree, and the count is shown.

ColourColours the tips by species, BIN, MOTU (when species were delimited), genus, country or species–BIN discordances (BIN with several species, species in several BINs, or both). There are eight colours; the remaining values show in grey as "Other".
BranchesPhylogram: branch length is proportional to distance. Cladogram: only the tree's shape, with tips aligned, easier to read when branches are very short.
Row / FontHeight of each row and font size. Below 5 px rows the labels are hidden.
LabelsWhat to show at each tip: species, ID, BIN, MOTU (when species were delimited), country. Coloured labels paints them in their group's colour (darkened where needed to stay readable).
Highlight species or ID…Highlights the tips matching the text and says how many there are.
Expand allUndoes every collapse.
Export figureAs shown (collapses, colours, labels): SVG (editable in Inkscape or Illustrator), PNG 2× or 4× (if the image would be too large it's made at a smaller scale and a notice says so) and PDF (the print dialog opens: choose "Save as PDF"; the browser must allow pop-ups).

How to interpret it

  • A barcode NJ tree is a clustering tool, not a phylogeny: it carries no support values (bootstrap), and deep relationships between genera or families aren't reliable from a single gene fragment.
  • What it does show well is whether each species forms a compact group of its own. Colour by species: a colour showing up on two separate branches of the tree is a split species (compare with the Species and BINs view); two colours mixed in one clade are species the marker doesn't separate.
  • In the phylogram, a long isolated branch leading to a single sequence is often a problem sequence (NUMT, contamination, many Ns) or a taxon very different from the rest.
  • Colouring by country helps see whether lineages within a species follow geography (e.g. an Andean clade and an Amazonian one).
🧪
Example. You analyse 800 COI-5P sequences of a bee genus. The tree opens collapsed by species (over 300 tips). You set Colour: Species–BIN discordances and see two orange triangles. Expanding the first, the sequences of Species X split into two well-separated subclades, one with samples from Mexico and the other from Costa Rica (you confirm it with Labels: Country), each with its own BIN: a cryptic species candidate. In the second, a single sequence identified as Species Y sits inside the clade of Species Z: most likely a misidentified specimen.

The results ZIP holds the tree in Newick format (tree.nwk) to open and edit in FigTree, iTOL or MEGA. Labels are processid|species|BIN.

Haplotype network

The Haplotype network tab draws how the haplotypes relate: each circle is a haplotype, its size the number of sequences, and each tick on a line one mutation. It is built on demand: choose a species (or every sequence in the analysis) in Sequences, the method, and press Build network. The Network button on each row of the Haplotypes tab builds it straight away for that species.

MethodHow it joins the haplotypesWhen to use it
TCS (default)
Clement, Posada & Crandall 2000		 Statistical parsimony, as PopART computes it: joins groups of haplotypes from the closest to the farthest through unsampled intermediate haplotypes (black dots), placed so that the network's paths match the observed differences as well as possible. Like PopART, it joins every group, without the 95 % connection limit. The usual network in barcoding and within-species phylogeography.
MSN
Bandelt, Forster & Röhl 1999		 Minimum spanning network: joins the haplotypes directly with the fewest mutations overall and keeps every equally short alternative, hence its loops. It adds no intermediates. Sets with many haplotypes (it takes more than TCS) or very divergent ones.

The sequences are aligned as for the distances and compared only over the positions every one of them has complete (A, C, G or T), so a shorter end or an N doesn't make a new haplotype. Those that would cover a much shorter region than the rest are left out, with a notice. That is why the number of haplotypes may differ from the Haplotypes tab, which doesn't align.

Above the network are the diversity statistics of those sequences: Hd (haplotype diversity), π (nucleotide diversity: the mean proportion of positions that differ between two sequences; k is the same as a number of differences), the segregating sites and Tajima's D.

ControlWhat it does
ColourSplits each circle by country, species, BIN or MOTU (when species were delimited, with the partition chosen there). Eight colours; the rest in grey as "Other".
LabelsThe haplotype's name (H1 is the commonest) and, optionally, its number of sequences.
Size / Mutation ticksThe figure's scale; without ticks each line shows its number of mutations (past 10 the number is always shown).
DragCircles can be dragged to arrange the figure; Reset layout goes back to the first one.
Export figureSVG, PNG 2× or 4× and PDF, as shown.
DataHaplotypes (CSV): each haplotype with its sequences, species, countries and BINs. Haplotypes (FASTA): one sequence per haplotype (the positions compared). NEXUS (PopART): one sequence per record with the colour chosen as traits (country when there is none), to go on in PopART.

How to read it

  • A large central haplotype with many rare ones one or two mutations away (a star) usually points to a recent population expansion, often with a negative Tajima's D.
  • Groups of haplotypes separated by many mutations (a number on the line) are divergent lineages: compare them with the MOTUs and the country to tell cryptic species from geographic lineages.
  • A haplotype shared by two species (a two-coloured circle when colouring by species) points to species the marker doesn't separate or an identification to check.
  • Read Tajima's D with great caution with few sequences (under 10) or samples from several populations.
ℹ️
TCS and MSN are implemented in the program itself and were checked against PopART: from the same sequences they give the same networks (same intermediate haplotypes and same connections). A network takes up to 2,000 sequences; TCS up to 300 haplotypes and MSN up to 600.

Worked example

Checking the quality of the barcodes of Brazil's cats:

  1. In Advanced field search: Family = Felidae AND Marker = COI-5P AND Country = Brazil. Press Search.
  2. Open the Sequence analysis tab, choose Results of the search on screen, leave Marker: Detect from the data and Genetic code: Automatic (it will use code 2, vertebrates) and press Analyse.
  3. In the summary, check the median length (~650 bp), the share meeting the barcode standard and that With stop codons is 0. In Composition and quality, review the flagged sequences.
  4. In Species and BINs, note the shared BINs and split species.
  5. In Distances, keep K2P, set Max. per species: 20 if a species has hundreds of sequences, and press Compute. Go through the automatic identification check first, then see which species have no barcode gap.
  6. In NJ tree, colour by species, find the problem species with Highlight and export the figure as SVG or PDF.
  7. Download the ZIP to keep the alignment, distances and Newick tree.

8 Frequently asked questions

How much disk space do I need?
BOLD's .tar.gz file is approximately 10–15 GB. The resulting SQLite database takes up between 20 and 30 GB. The FTS index (Step 4, optional) adds about another 25% on top of that. At least 80 GB free is recommended. Keep in mind that during Step 1 the .tar.gz, the extracted TSV, and the filtered TSV all temporarily coexist on disk.
Do I have to create any folder before building the database?
No. The program creates data/ and everything in it when it opens. You only need to drop the .tar.gz on the Start screen (or leave it in data/raw/).
Can I close the Creator while it's processing?
Closing the window stops the process. The Creator asks first and, if you confirm, stops the current step safely and closes on its own a few seconds later (it doesn't kill it halfway, which could damage the database). Reopen it and run the step again; the program detects the previous progress and resumes from the right place. Changing the language while a step is running is saved but only applies the next time you open the Creator.
The browser says "SERVER DISCONNECTED".
This means the server is no longer running: its terminal window was closed, or it closed by itself after the last viewer tab was closed. Open the BOLD-Local-DB Viewer shortcut again.
The "Full-text search" tab returns nothing.
It requires Step 4 (Full-text search). If you haven't run it, use the field search instead, which always works.
I searched Panthera leo without quotes in full-text search and got extra results.
Without quotes, each word is searched separately in any field (equivalent to Panthera AND leo), so a record can slip in if it contains "Panthera" in one field and "leo" in another, unrelated one. Use quotes — "Panthera leo" — to require that exact, contiguous sequence within the same field.
Searches are taking a long time.
Check that you ran Step 3 (Speed up searches). Also, the Contains, Does not contain, and Ends with operators can't take advantage of the indexes; prefer Equals or Starts with when possible.
Where do the files I export end up?
Your browser downloads them to your usual downloads folder, and a copy is also saved in data/exports/. For each export type, the 20 most recent files are kept.
Can I add or remove fields from the database?
Yes, from the Creator's Field Selection panel — see Choosing the fields. You can enable any of the 76 columns from BOLD's public data package, not just the 23 factory-default ones. A handful of fields (BOLD ID, Sample ID, BIN, basic taxonomy, Marker, Sequence) can't be removed because the viewer needs them to work.
I changed the field selection, saved it, but the viewer still shows the same thing.
Saving the selection only updates data/state/fields_config.json; the database doesn't change until you repeat Step 1 with BOLD's .tar.gz (the program detects the change and re-filters on its own). If the .tar.gz was already deleted, you'll need to download it again; to avoid that next time, tick "Keep the .tar.gz when done" in Step 1.
How often should I update the database?
BOLD publishes new versions weekly. To update, download the new .tar.gz, drop it on the Start screen (or place it in data/raw/) and choose Option 3 · Update the database: only what changed is applied. Rebuilding with Option 1 or 2 also works and is recommended now and then; see Resuming and updating.
Can I keep the database on an external drive?
Yes. Copy the whole program folder to the external drive and open it from there: any shortcuts you had made are remade to point at the new location.
What do I do if Step 1 says "Input not found" even though I put the file there?
Check that the file is directly inside data/raw/ and that its extension is .tar.gz (not just .tar or .gz). The program looks for exactly that format. If the Creator is still copying it (it shows up as .part), wait for the copy to finish.
Something failed and the message doesn't tell me enough.
Open data/state/logs/error.log: it contains the technical detail of the last error. The full history of each session is in data/state/logs/run_*.log.
Pressing "Analyse" asks me to choose a marker.
The input holds sequences of several markers (or a FASTA whose headers don't name it), and each analysis covers one. Pick the marker in the list, which shows how many sequences each has, and press Analyse again; those of other markers are left out. See Input and options.
The distance summary shows a huge largest distance within species (20–30 %) or 0 % between genera.
It is nearly always one or a few misidentified records: a sequence of another species under the wrong name inflates its species' largest distance and sinks the smallest one between species. The automatic identification check, at the top of the Distances tab, lists them with the species each is mistaken for. See also Before you start: distances and the barcode gap.
The distances say there are too many sequences.
The distance analysis takes up to 5,000 sequences (1,000 for non-coding markers) and the tree 2,000. Use Max. per species to keep a few sequences per species, or narrow the search (by genus, country, etc.). See Downloads and limits.
Almost all my COI sequences come out with stop codons.
It's nearly always the genetic code: if you forced it by hand (e.g. 1 · Standard for invertebrates), go back to Automatic. If it was already automatic, check that the marker is the right one and that the records have taxonomy (without it, code 5 is used). See the example.
